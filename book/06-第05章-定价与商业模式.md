# 第 5 章　定价与商业模式：token、席位、任务与结果

> 定价是营销中最被低估的环节。一个好的价格本身就是一句广告，一个坏的价格会让所有的广告失效。

## 5.1 为什么 Agent 定价特别难

在传统软件行业，定价虽然也不简单，但已经形成了相对成熟的惯例：个人软件按年或按月订阅，企业 SaaS 按席位订阅，私有化软件按许可证加维保收费。客户知道该怎么比较，销售知道该怎么报价。

Agent 打破了这些惯例。Agent 定价特别难，原因有三个"可变"：

**第一，成本是可变的。**传统软件的边际成本接近于零，多服务一个用户几乎不增加成本。Agent 每完成一个任务都要消耗算力，而且不同任务的消耗差异巨大：一个简单的问答可能只消耗几千个 token，一个复杂的编程任务可能需要 Agent 反复阅读代码、运行测试、修改重试，消耗几百万个 token。如果你按固定价格收费，重度用户可能让你严重亏损；如果你按用量收费，客户又会担心成本失控。

**第二，价值是可变的。**同样是"修复一个缺陷"，有的缺陷人工十分钟就能修好，有的需要一个资深工程师花一整天。同样是"完成一次对账"，有的供应商只有几笔交易，有的有上千笔。Agent 交付的价值在不同任务之间差异巨大，很难找到一个统一的计价单位。

**第三，参照是可变的。**客户用什么作为价格参照？和其他软件比，Agent 显得很贵；和人工成本比，Agent 又显得很便宜。和海外产品比、和大厂免费产品比、和外包服务比，得出的结论完全不同。参照物不明确，客户就无法判断价格是否合理。

此外，中国市场还有一个特殊的复杂因素：**价格战留下的低价锚点**。经过几轮模型价格战，"AI 很便宜甚至免费"已经成为很多客户的默认认知。当你报出一个有利润的价格时，客户可能会说："某某大厂的模型 API 才几毛钱一百万 token，你为什么这么贵？"

面对这些困难，我们需要一套系统的方法来设计 Agent 的定价。

## 5.2 五种计费模式

目前市场上 Agent 产品的计费模式大致可以分为五种。

### 模式一：按席位订阅

**方式**：每个用户每月或每年支付固定费用，在一定范围内不限量使用（或有较宽松的用量上限）。

**优点**：客户熟悉，预算可预测，销售简单；适合客户对成本确定性要求高的场景。

**缺点**：与 Agent 的价值逻辑存在冲突——Agent 越能干，客户需要的人就越少，需要的席位也越少；重度用户可能造成成本亏损；不同用户的使用强度差异大，按人收费不公平。

**适用场景**：Agent 作为个人效率工具（如编程助手、写作助手），用户使用强度相对平均的场景。

### 模式二：按用量计费

**方式**：按实际消耗的 token、调用次数、算力时长、处理的文档页数等计费。

**优点**：成本和收入天然匹配，不会因重度用户亏损；对轻度用户友好，门槛低；适合开发者和技术型客户。

**缺点**：客户难以预测成本，容易产生"用量焦虑"；token 等计量单位对非技术客户来说难以理解；客户可能因为担心费用而减少使用，抑制价值的产生。

**适用场景**：API 和平台型产品、开发者工具、用量波动大的场景。

### 模式三：按任务计费

**方式**：按 Agent 完成的任务数量计费，比如每份报告多少钱、每次对账多少钱、每个工单多少钱。

**优点**：客户容易理解，直接和工作量挂钩；比 token 更接近客户的价值感知；预算相对可预测。

**缺点**：不同任务的复杂度差异大，需要合理定义"一个任务"；Agent 失败的任务是否收费需要明确；可能鼓励把任务拆碎以减少费用，或者合并以增加单次处理量。

**适用场景**：任务边界清晰、复杂度相对稳定的业务流程型 Agent。

### 模式四：按结果计费

**方式**：只为成功的结果付费，比如每成功解决一个客服工单收费、每成功识别一处对账差异收费、按节省的成本分成。

**优点**：与客户价值高度一致，最能体现"卖结果"的理念；风险转移给供应商，降低客户的决策门槛；在竞争中有很强的说服力。

**缺点**：需要清晰定义"成功"，并且双方都认可的衡量方式；供应商承担较大风险；结果的归因可能存在争议（成本节省是 Agent 的功劳还是其他因素的功劳？）；收入的可预测性差。

**适用场景**：结果高度可衡量的场景，比如客服解决率、线索转化、成本节省。

### 模式五：混合计费

**方式**：组合使用以上多种模式。最常见的形式是"基础订阅费 + 包含用量 + 超额按量计费"，或者"平台费 + 按任务计费"。

**优点**：兼顾预算可预测性和成本匹配；可以灵活适应不同客户；基础费用保证了收入下限。

**缺点**：复杂度较高，需要清晰的沟通；容易让客户觉得"套路多"。

**适用场景**：目前多数成熟的 Agent 产品都在采用某种形式的混合计费。

### 五种模式对比

| 模式 | 客户理解难度 | 预算可预测性 | 成本匹配度 | 价值一致性 | 中国市场接受度 |
|---|---|---|---|---|---|
| 按席位订阅 | 低 | 高 | 低 | 低 | 高（个人与中小企业） |
| 按用量计费 | 中到高 | 低 | 高 | 中 | 中（开发者较高） |
| 按任务计费 | 低 | 中 | 中 | 中到高 | 中到高 |
| 按结果计费 | 低 | 低 | 中 | 高 | 中（取决于信任） |
| 混合计费 | 中 | 中到高 | 高 | 中到高 | 高（需沟通清楚） |

### 海外标杆的思路

观察海外 Agent 产品的定价实践，可以看到一个普遍的模式：**面向个人的订阅套餐分为多个档位，档位之间的主要差别是用量额度**；面向团队和企业的版本增加管理、安全、合规功能，按席位收费并提供更高的额度；面向开发者的 API 则按 token 计费。以 Claude、ChatGPT 为代表的产品，都提供了从入门到高额度的多档个人订阅，高档位主要服务于重度使用编程智能体等高消耗场景的用户。

这种"订阅档位 + 用量额度"的设计，本质上是用订阅的形式提供可预测性，用额度的差异实现成本匹配和价格歧视。它对中国市场有参考价值，但需要结合本地情况调整。

## 5.3 中国市场的定价现实

### 现实一：个人付费的价格敏感

中国个人用户对软件订阅的价格敏感度较高。海外产品常见的每月数十美元的订阅价，换算成人民币后对很多中国个人用户来说门槛不低。国内的个人订阅产品通常需要更低的入门价格，同时利用年付折扣、连续包月优惠、首月特价等方式提升转化。

但需要注意，**开发者等专业人群的付费意愿正在快速提升**。当一个工具能够实实在在地每天节省一两个小时时，一个月花几百元并不是难以接受的事情，尤其是当公司愿意报销的时候。关键在于价值是否被清晰地感知。

### 现实二：企业偏好确定性

中国企业的财务管理通常以年度预算为基础，对"不确定的费用"有天然的排斥。按用量计费的产品在企业采购时经常遇到这样的问题："这个费用到底是多少？我怎么做预算？万一超了谁批？"

因此，面向中国企业客户，**提供一个可预测的年度总价**几乎是必须的。常见的做法包括：年度包量（买一定量的使用额度，用完可以追加）、封顶计费（用量超过一定程度后不再加收）、固定年费加公平使用条款。

### 现实三：私有化部署的定价

如前所述，中国大中型企业和政企客户普遍偏好私有化部署。私有化部署的定价通常由以下几部分组成：

- **软件许可费**：一次性买断或按年订阅。传统软件多采用买断制，但对于需要持续迭代的 Agent 产品，按年订阅越来越被接受。
- **实施服务费**：部署、集成、配置、定制开发、培训，通常按人天计算。
- **维保服务费**：买断模式下的年度维护和升级服务，通常为许可费的一定比例。
- **硬件与算力成本**：如果需要客户自备 GPU 服务器或采购一体机，这部分成本可能非常可观，需要在方案中明确。
- **模型授权费**：如果使用了需要授权的商业模型，可能有额外的模型授权费用。

私有化部署的定价挑战在于：**交付成本难以标准化**。每个客户的环境不同、集成需求不同，实施工作量差异很大。如果实施费报得太低，项目可能亏损；报得太高，客户可能接受不了。建议的做法是：标准化产品部分，模块化实施部分，为常见的集成需求制定标准报价，非标需求单独评估。

### 现实四：一体机模式

2025 年以来，"大模型一体机"在中国政企市场成为一个热门品类：把服务器硬件、国产算力、开源大模型、Agent 应用打包成一个开箱即用的设备销售。这种模式迎合了政企客户"买一个看得见摸得着的东西"、"数据完全在本地"的需求，也便于走硬件采购流程。

对于 Agent 厂商来说，一体机是一个值得考虑的渠道，但也要注意：一体机的价格竞争激烈，硬件利润薄，Agent 软件的价值容易被淹没在硬件价格里。如果选择这条路，应该争取让 Agent 软件单独计价，或者通过后续的应用扩展和服务获取持续收入。

### 现实五：招投标中的价格竞争

在政府和国企采购中，价格往往是评分的重要因素，有时甚至出现"低价中标"的现象。这对 Agent 厂商提出了挑战：一方面要在价格上保持竞争力，另一方面又要避免以亏损价格中标后无法保证交付质量。我们会在第 12 章详细讨论这个问题。

## 5.4 定价设计五步法

面对这些复杂的情况，我们推荐一个五步法来设计 Agent 的定价。

### 第一步：找到价值度量单位

**价值度量单位**（value metric）是你向客户收费的依据，它应该满足三个条件：

1. **与客户价值相关**：度量单位增加时，客户获得的价值也在增加。
2. **客户容易理解**：客户能够清楚地知道自己用了多少、会用多少。
3. **与你的成本大致匹配**：度量单位增加时，你的成本也相应增加。

对于不同类型的 Agent，可选的价值度量单位不同：

| Agent 类型 | 可选的价值度量单位 |
|---|---|
| 编程智能体 | 席位、任务数、计算额度、代码仓库数 |
| 客服智能体 | 会话数、解决的工单数、坐席数 |
| 财务智能体 | 处理的单据数、对账的供应商数、处理的发票数 |
| 数据分析智能体 | 报告数、数据源数、查询次数 |
| 营销内容智能体 | 生成的内容篇数、管理的账号数 |
| Agent 开发平台 | token 消耗、Agent 运行时长、部署的 Agent 数量 |

选择价值度量单位时，**尽量选择客户业务中已有的计量单位**，而不是技术性的计量单位。比如对财务部门来说，"对账的供应商数"比"消耗的 token 数"直观得多；对客服部门来说，"解决的工单数"比"调用次数"更有意义。

### 第二步：计算成本底线

在定价之前，你必须清楚地知道服务一个客户、完成一个任务的成本是多少。Agent 的成本包括：

- **模型调用成本**：这是最大的变动成本。需要统计不同类型任务的平均 token 消耗，以及消耗的分布（尤其是长尾的高消耗任务）。
- **基础设施成本**：沙箱环境、存储、网络、日志等。
- **工具调用成本**：调用第三方 API、搜索服务、数据服务的费用。
- **人工成本**：人工审核、客户支持、实施交付的成本。

一个关键的提醒：**不要只看平均成本，要看成本分布**。Agent 任务的成本往往呈现长尾分布：大多数任务成本不高，但少数复杂任务的成本可能是平均值的几十倍甚至上百倍。如果定价只覆盖平均成本，少数重度用户就可能吃掉你的全部利润。

另一个关键的提醒：**模型成本在持续下降**。过去几年，同等能力的模型调用价格下降非常快。在定价时既要覆盖当前成本，也要考虑未来成本下降带来的利润空间——这部分空间可以用于后续的降价竞争，也可以用于提升服务质量。

### 第三步：找到参照锚点

客户会用什么来评判你的价格是否合理？你需要主动为客户设定一个有利的参照锚点。

**最有利的锚点是人工成本。**"这个 Agent 每月的费用，相当于一个初级员工每月工资的十分之一。""完成一次对账，人工需要两天，Agent 的费用不到人工成本的二十分之一。"把 Agent 的价格放在人工成本的参照系中，它显得非常划算。

**最不利的锚点是模型 API 价格。**如果客户拿你的价格和底层模型 API 价格比，你永远显得很贵。要主动引导客户理解：Agent 的价值不在于 token，而在于把 token 组织成完成的工作——就像一个装修公司的价值不在于砖头和水泥的价格。

**中性的锚点是其他软件。**和同类 SaaS 软件、RPA 软件、外包服务比较，需要突出 Agent 的增量价值。

### 第四步：设计套餐梯度

好的套餐设计能够同时服务不同类型的客户，并引导客户升级。Agent 产品的套餐设计建议遵循以下原则：

1. **三到四个档位为宜**。档位太少无法覆盖不同需求，档位太多会让客户困惑。
2. **入门档位降低门槛**。可以是免费版或低价版，让客户以极低的成本体验核心价值。
3. **主力档位锁定目标客户**。这是你希望大多数客户购买的档位，定价和权益设计要让它看起来"最划算"。
4. **高级档位服务重度用户和锚定价格**。它的存在一方面满足重度用户的需求，另一方面让主力档位显得更有吸引力。
5. **企业档位提供管理与安全能力**。企业客户需要的不只是更多的用量，还有单点登录、权限管理、审计日志、数据隔离、专属支持、合规承诺等能力。这些能力是企业档位溢价的主要来源。

一个示意性的套餐结构：

| 档位 | 目标客户 | 核心权益 | 定价思路 |
|---|---|---|---|
| 免费版 | 尝鲜个人用户 | 有限的任务额度，基础能力 | 获客成本，控制在可承受范围 |
| 专业版 | 个人专业用户 | 充足的日常额度，完整能力 | 主力档位，对标个人工具类订阅 |
| 高额度版 | 重度个人用户 | 数倍于专业版的额度，优先资源 | 覆盖重度用户成本，锚定价格 |
| 团队版 | 小团队 | 按席位，共享额度池，团队管理 | 按席位加额度 |
| 企业版 | 中大型企业 | 安全合规、私有部署选项、专属支持 | 定制报价，年度合同 |

### 第五步：设计护栏

Agent 定价必须设计护栏，防止成本失控和客户体验受损。

**对供应商的护栏**：

- **用量上限与公平使用条款**：即使是"不限量"的套餐，也要设置合理的公平使用条款，防止极端用户和滥用。
- **速率限制**：限制单位时间内的使用量，平滑算力消耗。
- **任务复杂度分级**：对特别复杂的任务（比如需要长时间运行的任务）单独计费或提示用户。

**对客户的护栏**：

- **预算上限设置**：允许客户设置月度或项目预算上限，达到上限时自动暂停或提醒。
- **用量预警**：在用量达到一定比例时主动通知客户。
- **成本预估**：在执行大型任务前，向用户预估可能的成本。
- **超额规则透明**：清楚说明超出额度后会发生什么——是暂停服务、降级服务还是按量计费。

客户护栏不仅是一种保护，还是一种**营销卖点**。"永远不会有意外账单"这句话，对于担心成本失控的企业客户来说，可能比任何功能介绍都更有吸引力。

## 5.5 免费策略：送什么、送多少、送给谁

免费是中国市场最有力的获客手段之一，但 Agent 的免费策略必须精心设计，因为每一次免费使用都有真实的成本。

### 四种常见的免费形式

1. **免费额度**：每个用户每月有一定的免费使用额度。适合建立长期使用习惯，但需要控制额度大小。
2. **限时免费试用**：新用户可以在一定时间内（比如七天或十四天）免费使用完整功能。适合让用户快速体验核心价值，但需要确保用户在试用期内能完成"首次成功"（见第 10 章）。
3. **开源或社区版**：开源 Agent 的核心框架或基础版本，商业版提供增值能力。适合开发者工具和平台型产品（见第 9 章）。
4. **定向免费**：对特定人群提供免费或大幅优惠，比如学生、教师、开源项目维护者、非营利组织、初创企业。适合建立口碑和培养未来用户。

### 免费策略的三条原则

**原则一：免费要送"Aha 时刻"，而不是送"无限用量"。**免费额度的设计目标应该是让用户恰好能够体验到核心价值——完成一个让他惊喜的任务——然后自然产生付费需求。额度太少，用户还没体验到价值就用完了；额度太多，用户没有理由付费。

**原则二：免费的成本要可控。**设置每日或每月的总预算上限，设置单个用户的用量上限，监控异常使用（比如批量注册薅羊毛），在免费用户中优先使用成本较低的模型或资源。

**原则三：免费要有转化路径。**免费用户使用到一定程度时，要有清晰的升级提示和转化路径。最好的转化时机是用户刚刚体验到价值、并且需要更多的时候。

### 警惕"免费陷阱"

我们见过不少 Agent 产品因为免费策略失误而陷入困境：为了追求用户数量，提供了大量免费额度，结果用户数量快速增长，算力成本也随之快速增长，而付费转化率远低于预期。最终，团队不得不削减免费额度，又引发了用户的不满和负面舆论。

**免费额度一旦给出，就很难收回。**所以，宁可开始时保守一些，再根据数据逐步放宽，也不要一开始就过于慷慨。

## 5.6 计费体验也是产品体验

很多 Agent 团队把计费当作一个纯粹的商业问题，交给财务和运营去处理。实际上，**计费体验是产品体验的重要组成部分**，对用户满意度和口碑有直接影响。

### 用量焦虑

按用量计费的 Agent 产品，用户普遍存在一种"用量焦虑"：每次使用 Agent 都在担心"这个任务会花多少钱""额度还剩多少""会不会突然被限流"。这种焦虑会显著降低用户的使用意愿，进而降低 Agent 的价值产出。

缓解用量焦虑的方法包括：

- **实时用量看板**：让用户随时清楚地看到已用多少、剩余多少。
- **任务前预估**：在执行可能消耗较多资源的任务前，给出预估。
- **温和的限额处理**：额度用完时，不要突然中断正在执行的任务，而是让当前任务完成后再提示。
- **清晰的额度说明**：用客户能理解的方式说明额度，比如"大约可以完成 XX 个中等复杂度的任务"，而不是只给一个 token 数字。

### 账单的可读性

企业客户的财务人员需要看懂账单。一份好的 Agent 账单应该：

- 按部门、项目、用户分别列出用量和费用，方便内部分摊；
- 用业务语言说明费用的构成，而不是只列出技术指标；
- 提供与上期的对比和趋势；
- 支持导出，方便与企业的财务系统对接；
- 符合中国企业的开票习惯，能够及时开具增值税发票。

最后一点看似琐碎，但对于中国企业客户来说极其重要。**开票不及时、发票类目不对、无法按照企业要求的方式开票**，都可能导致企业无法报销或入账，进而影响续费。

## 5.7 如何沟通价格

定好价格之后，如何向客户沟通价格同样重要。

### 原则一：先讲价值，再讲价格

永远不要在客户还没有理解价值的时候报价。在报价之前，应该先和客户一起算清楚价值账——用第 1 章的净交付价值公式，或者用一个简单的 ROI 计算器。当客户已经认可"这件事每月能帮我省下 X 万元"时，再报出"每月费用是 X 千元"，客户的感受会完全不同。

### 原则二：用客户的语言说价格

不要说"每百万 token 多少钱"，要说"每处理一份合同多少钱""每个工程师每天不到一杯咖啡的钱"。把价格翻译成客户熟悉的计量单位和参照物。

### 原则三：提供 ROI 计算器

在官网上或销售工具中提供一个简单的 ROI 计算器：客户输入团队规模、任务频次、人工耗时、人力成本等参数，计算器给出预计节省的时间和成本，以及 Agent 的费用和投资回报周期。这种工具不仅能帮助客户做决策，还能帮助客户向上级汇报——"这是我算的账"。

### 原则四：透明胜于复杂

中国客户普遍反感"套路"。复杂的计费规则、隐藏的附加费用、模糊的超额条款，都会严重损害信任。尽量让价格结构简单透明，把所有可能的费用都清楚地列出来。

## 5.8 如何应对价格战

在中国 AI 市场，价格战几乎是不可避免的。当竞争对手——尤其是资金雄厚的大厂——大幅降价甚至免费时，你应该怎么办？

### 策略一：不跟——讲价值差异

如果你的产品在某个场景中有明显的价值优势（更高的完成率、更低的监督成本、更好的服务），就不要轻易跟随降价，而是强化价值差异的沟通。"免费的工具，需要你花三小时来检查和修改；我们的 Agent，你只需要花十分钟验收。"用净交付价值的逻辑，说明便宜的不一定划算。

### 策略二：错位跟——在非核心层降价

在不影响核心价值的层面降价，比如降低入门门槛（推出更便宜的入门套餐）、提供更多的免费额度、对特定群体（学生、初创企业）大幅优惠，同时保持核心套餐和企业套餐的价格稳定。

### 策略三：差异化跟——改变计费方式

当对手在某个计费维度上压价时，换一个维度竞争。比如对手按 token 大幅降价，你可以推出按结果计费：只为成功的结果付费。这样客户就无法直接比较价格，而是要比较"谁能更好地完成任务"。

### 策略四：借力——利用模型降价

大厂之间的模型价格战，对应用层 Agent 公司来说其实是利好：你的模型调用成本在下降。你可以把一部分成本下降的红利让给客户，保持价格竞争力；把另一部分转化为利润或投入到产品和服务中。

### 不要做的事

- **不要为了抢客户而以低于成本的价格长期销售**。除非你有充足的资金并且有清晰的规模化降本路径，否则这是在透支未来。
- **不要频繁调价**。频繁调价会让客户对你的价格失去信任，也会让已付费的客户感到不公平。
- **不要在降价后偷偷降低服务质量**。这种做法一旦被发现，会对品牌造成严重伤害。

## 5.9 案例：一家客服 Agent 公司的定价演变

> 以下为综合化、匿名化案例，公司名为化名，数字为示意。

"知音智服"是一家面向电商和消费品牌的客服 Agent 公司。它的定价经历了三个阶段的演变。

**第一阶段：按坐席收费。**沿用传统客服软件的习惯，按照客服坐席数量收费。问题很快暴露：客户用了 Agent 之后，人工坐席减少了，按坐席收费的收入也随之减少——产品越成功，收入越少。

**第二阶段：按会话量收费。**改为按 Agent 处理的会话数量收费。收入和使用量挂钩了，但新的问题出现：客户抱怨 Agent 处理了很多"无效会话"（比如用户只说了一句"在吗"就离开了），这些也被计费；而且在大促期间，会话量暴增，客户的费用也暴增，财务部门很难做预算。

**第三阶段：基础费 + 按解决量收费 + 大促封顶。**最终，知音智服设计了一个混合模式：每月收取一笔固定的平台费，覆盖基础服务和一定量的会话；超出部分只对"**被 Agent 独立解决**"的会话收费（客户未转人工、未在一定时间内再次咨询同一问题），而转人工或未解决的会话不收费；在大促期间设置费用封顶。

这个模式带来了几个显著的效果：

- **销售更容易**：客户听到"只为解决的问题付费"，决策门槛大幅降低；
- **激励更一致**：知音智服有动力持续提升 Agent 的解决率，因为这直接决定了收入；
- **预算可预测**：固定平台费加封顶机制，让财务部门可以做出准确的预算；
- **口碑更好**：客户感到公平，愿意推荐给同行。

当然，这个模式也带来了新的挑战：需要和客户就"解决"的定义达成一致，需要建立透明的数据统计和对账机制。知音智服为此开发了一个"解决率看板"，客户可以实时查看每一个会话的处理结果和计费状态。这个看板后来也成了销售演示中最有说服力的部分。

### 案例启示

1. **按席位收费与 Agent 的价值逻辑存在根本冲突**，产品越成功，收入可能越少。
2. **按用量收费要区分"有效用量"和"无效用量"**，否则会损害客户的公平感。
3. **按结果收费最能体现 Agent 的价值**，但需要清晰的定义和透明的衡量机制。
4. **企业客户需要预算可预测性**，封顶机制是一个有效的解决方案。
5. **透明的计费机制本身就是营销资产。**

## 本章要点

1. Agent 定价特别难，因为成本、价值和参照都是可变的。中国市场还有价格战留下的低价锚点。
2. 五种计费模式：按席位订阅、按用量计费、按任务计费、按结果计费、混合计费。目前多数成熟的 Agent 产品采用某种形式的混合计费。
3. 中国市场的定价现实：个人付费价格敏感但专业人群付费意愿在提升；企业偏好预算确定性；私有化部署需要拆分许可、实施、维保、硬件等多项费用；一体机是政企市场的热门形态；招投标中存在价格竞争。
4. 定价设计五步法：找到价值度量单位 → 计算成本底线（看分布不只看平均）→ 找到参照锚点（人工成本最有利）→ 设计套餐梯度 → 设计护栏。
5. 免费要送"Aha 时刻"而不是"无限用量"，免费成本要可控，要有转化路径。免费额度一旦给出就很难收回。
6. 计费体验是产品体验的一部分：缓解用量焦虑，账单可读，开票及时。
7. 应对价格战的四种策略：讲价值差异、在非核心层降价、改变计费方式、借力模型降价。
