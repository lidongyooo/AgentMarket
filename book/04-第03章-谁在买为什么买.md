# 第 3 章　谁在买、为什么买：中国 Agent 用户与购买决策链

> 不要问"谁会需要 AI"，每个人都会说需要。要问"谁会为了让 AI 替他干活而掏钱，以及他掏钱之前要过几道关"。

## 3.1 五层客户金字塔

Agent 产品的客户可以按照"决策主体"和"购买规模"分为五层，我们称之为**五层客户金字塔**。从塔尖到塔基分别是：

1. **政企与国央企**：政府机构、事业单位、国有企业、中央企业。
2. **中大型企业**：员工数百人以上，有独立 IT 部门和规范采购流程的民营企业、外资企业、上市公司。
3. **小团队与中小企业**：几人到上百人的企业或团队，决策相对集中，往往老板一人拍板。
4. **专业个人**：开发者、设计师、内容创作者、咨询顾问、律师、分析师等知识工作者，他们为了工作效率自己付费或申请报销。
5. **大众个人用户**：普通消费者，为生活便利、学习、娱乐使用 AI。

这五层客户在需求、预算、决策方式和营销方法上差别巨大。

| 层级 | 典型客单价（示意） | 决策周期 | 决策关键人 | 核心诉求 | 主要营销方式 |
|---|---|---|---|---|---|
| 政企与国央企 | 数十万到数千万元 | 半年到两年 | 领导班子、信息中心、采购 | 安全可控、合规、示范效应 | 标杆项目、资质、生态伙伴、行业会议 |
| 中大型企业 | 数万到数百万元 | 一到六个月 | 业务负责人、CIO/CTO、采购 | 降本增效、可集成、可管理 | 直销、POC、行业案例、渠道 |
| 小团队与中小企业 | 数百到数万元/年 | 数天到一个月 | 老板或团队负责人 | 简单、便宜、立竿见影 | 口碑、内容、平台入口、私域 |
| 专业个人 | 数十到数百元/月 | 即时到数天 | 用户本人 | 效率、能力增强、职业竞争力 | 社区、内容、免费试用、口碑 |
| 大众个人用户 | 免费到数十元/月 | 即时 | 用户本人 | 好玩、便利、省事 | 社交传播、应用商店、平台合作 |

在资源有限的情况下，**任何一家 Agent 公司都不应该同时攻打全部五层**。大多数成功的 Agent 产品都是从一层切入，建立根据地后再向相邻层级扩张。常见的扩张路径有两条：

- **自下而上**：从专业个人切入（比如开发者），通过个人使用的口碑渗透到团队，再从团队进入企业。编程智能体大多走这条路。
- **自上而下**：从中大型企业或政企切入，以项目和解决方案打开市场，再把成熟的能力产品化，向中小企业下沉。业务流程型 Agent 大多走这条路。

下面我们逐层分析。

## 3.2 大众个人用户：最大的市场，最难的生意

### 画像

大众个人用户使用 AI 的动机大致有四种：

- **好奇型**：被热点吸引，想看看 AI 到底能干什么。来得快，走得也快。
- **焦虑型**：担心"不会用 AI 就会被淘汰"，希望通过使用 AI 获得安全感。这一群体在 2025 年以来显著扩大，"AI 焦虑"成为中国社交媒体上的高频话题。
- **效率型**：有具体的任务需要完成——写周报、做 PPT、整理资料、规划旅行、辅导孩子作业，希望 AI 帮忙省时间。
- **陪伴与娱乐型**：把 AI 当作聊天对象、创作伙伴或游戏玩法。

### 付费心理

中国大众用户的付费心理有几个鲜明特点：

- **价格锚点低**。很多用户会下意识地拿视频会员、音乐会员的价格作为参照，每月十几到几十元是常见的心理价位。
- **免费替代多**。各大厂的 AI 助手大多可以免费使用，且能力不断增强。用户会问："免费的已经够用了，为什么要付费？"
- **为"结果"付费比为"能力"付费更容易**。用户不太愿意为"更强的模型"付费，但愿意为"一份做好的简历""一套完成的 PPT""一个规划好的行程"付费。
- **冲动消费与连续包月**。低价首月、限时折扣、连续包月等方式在中国用户中非常有效，但也容易带来高退订率和投诉风险。

### 营销判断

对于大多数 Agent 创业公司而言，大众个人用户市场是一个**"看起来最大、实际上最难"**的市场。原因是：大厂免费产品构成了强大的替代；用户获取成本高；留存难；付费率低；监管要求高（面向公众提供生成式 AI 服务需要完成相应合规手续）。

如果你决定进入这个市场，建议：

1. **聚焦一个高频、具体、可交付的任务**，而不是做"全能助理"。比如"帮你把会议录音变成纪要并发给参会人"，而不是"你的 AI 私人助理"。
2. **按结果定价**，让用户为一个完成的成果付费，降低决策门槛。
3. **把传播内置在产品里**：Agent 交付的成果本身就带有传播属性（比如精美的报告、可分享的链接），让每一次使用都可能带来新用户。
4. **严格管理期望**，避免过度营销导致的口碑反噬。

## 3.3 专业个人：Agent 的第一块根据地

### 为什么是专业个人

专业个人——尤其是开发者——是当前 Agent 产品最重要的根据地。原因有四：

1. **任务价值高**。专业人士的时间值钱，节省一小时的价值远高于普通用户。
2. **任务可验证**。代码可以测试，设计可以评审，文案可以对照需求，专业人士有能力判断 Agent 的工作质量。
3. **付费意愿强**。专业人士习惯为工具付费，也更容易算清楚"花一百块换回十个小时"这笔账。
4. **影响力大**。专业人士在团队和公司中往往是工具选型的意见领袖，他们的推荐可以把个人使用变成团队采购。

### 开发者画像：中国最重要的 Agent 早期用户

中国拥有规模庞大的软件开发者群体。根据开发者在 Agent 采纳上的特征，我们可以把他们分为四类：

**学生与初级开发者**：学习意愿强，对新工具接受度高，但付费能力有限。他们是重要的口碑传播者和未来用户，适合用免费额度、教育优惠、校园活动来覆盖。

**业务开发者**：在企业中承担大量日常开发任务，是编程智能体最核心的用户群体。他们最关心的是：能不能真正节省时间，能不能理解公司的代码库，会不会引入难以发现的 bug，公司是否允许使用。

**资深开发者与架构师**：对代码质量和系统设计有很高要求，对 AI 工具往往持审慎甚至怀疑态度。一旦被说服，他们会成为最有分量的推荐者。他们关心的是：Agent 能否处理复杂的跨文件修改，能否遵守团队规范，能否在大型代码库中保持准确。

**技术管理者**：技术负责人、研发总监、CTO。他们关心的是团队整体效率、代码安全、成本控制、合规风险，以及如何衡量 AI 工具的投入产出。他们是从"个人使用"到"团队采购"的关键决策者。

### 开发者的信息获取渠道

中国开发者获取技术信息和工具推荐的渠道非常多元：

- **代码与开源平台**：GitHub、Gitee。
- **技术社区**：掘金、CSDN、思否（SegmentFault）、开源中国、V2EX、博客园、InfoQ 等。
- **综合内容平台**：知乎（技术问答）、B 站（技术视频、教程）、微信公众号（技术文章）、小红书（越来越多的程序员在这里分享效率工具）、即刻等。
- **社群**：微信群、技术交流群、Discord 和 Telegram 社群。
- **线下活动**：技术大会、meetup、黑客松、高校讲座。

我们会在第 7 章详细讨论如何针对开发者做营销。

### 其他专业个人

除了开发者，以下专业人群也是 Agent 产品的重要目标：

- **内容创作者与自媒体人**：需要大量的资料整理、选题研究、文案撰写、视频脚本、数据分析工作。
- **咨询顾问与分析师**：需要快速完成行业研究、竞品分析、报告撰写。
- **律师与法务**：合同审查、法律检索、文书起草。
- **财务与审计人员**：对账、报表分析、审计底稿整理。
- **电商运营人员**：商品上架、详情页文案、客服话术、数据分析、竞品监控。
- **设计师与产品经理**：需求文档、原型、竞品研究、用户研究资料整理。

这些人群的共同特点是：工作中有大量**可描述、可拆解、可验证**的任务，并且时间成本较高。

## 3.4 小团队与中小企业：老板说了算

### 画像

中国有数量庞大的中小企业和个体工商户。它们的特点是：

- **决策高度集中**。老板往往一人拍板，决策速度快。
- **对价格敏感，对效果务实**。不会为"概念"买单，但会为"马上能用、马上见效"买单。
- **IT 能力有限**。大多没有专门的 IT 人员，无法进行复杂的部署和集成。
- **受同行影响大**。"隔壁老王用了效果很好"比任何广告都管用。
- **生态依赖重**。大量的业务运行在微信、抖音、淘宝、拼多多、美团等平台上，办公依赖钉钉、飞书或企业微信。

### 老板的三个问题

和中小企业老板打交道，你会发现他们最关心的永远是三个问题：

1. **"能帮我省几个人？"**——人力成本是中小企业最大的痛点之一。
2. **"能帮我多赚多少钱？"**——更多的客户、更快的响应、更高的转化。
3. **"我的员工能不能用起来？"**——老板买了工具，员工不用，是中小企业最常见的软件采购失败模式。

### 营销判断

中小企业市场的营销关键在于**"简单"**：

- 产品简单：开箱即用，最好在已有的平台（钉钉、飞书、企业微信、微信）里直接用。
- 价格简单：明码标价，不要复杂的计费方式。
- 价值简单：用一句话、一个数字讲清楚能省什么、能赚什么。
- 购买简单：线上即可购买，不需要复杂的合同流程。

渠道上，**同行口碑、行业社群、平台生态、本地服务商**是触达中小企业最有效的方式。我们会在第 13 章讨论如何通过渠道伙伴覆盖中小企业市场。

## 3.5 中大型企业：多角色、长链条的集体决策

### 购买决策中的六种角色

中大型企业的 Agent 采购是一个集体决策过程，通常涉及以下六种角色：

| 角色 | 典型职位 | 关注点 | 营销与销售策略 |
|---|---|---|---|
| **发起者** | 业务部门负责人、技术骨干、数字化负责人 | 解决自己的业务痛点，做出业绩 | 提供能帮他"向上汇报"的材料和数据 |
| **使用者** | 一线员工、开发者、客服、运营 | 好不好用，会不会增加工作量，会不会威胁岗位 | 让他们参与试点，倾听反馈，强调"减负"而非"替代" |
| **决策者** | 总经理、CIO、CTO、CDO，或分管领导 | 战略价值、投入产出、风险 | 讲战略、讲行业趋势、讲同行标杆 |
| **把关者** | 信息安全、法务、合规、IT 架构 | 数据安全、合规风险、技术兼容 | 提前准备安全白皮书、合规材料、架构文档 |
| **采购者** | 采购部门 | 价格、合同条款、供应商资质 | 规范的报价、资质文件、合同模板 |
| **财务** | 财务部门 | 预算、成本可预测性 | 可预测的计费模式、清晰的成本模型 |

一个常见的错误是只盯着发起者或决策者，而忽视了把关者。在 Agent 采购中，**信息安全和法务往往拥有一票否决权**。很多项目在业务部门和领导都点头之后，卡在安全评审或法务审核环节长达数月，甚至最终被否决。

所以，Agent 销售必须做到"**多线并进**"：在打动发起者和决策者的同时，尽早让把关者介入，提前解决他们的顾虑。

### 中国企业决策的几个特殊现象

**"一把手工程"**。在中国企业中，AI 转型常常被定位为"一把手工程"。如果企业一把手亲自推动，项目推进速度会快得多；如果一把手不重视，再好的产品也很难在组织内落地。因此，**接触并影响一把手**是大客户营销的重要目标。高端闭门会、行业峰会、标杆企业参访、高管培训等形式，是接触一把手的常见途径。

**"同行标杆效应"**。中国企业非常看重同行的做法。"同行业的头部企业用了吗？""有没有同规模企业的成功案例？"是销售过程中最常被问到的问题。一个行业内有影响力的标杆客户，可以撬动整个行业。

**"预算节奏"**。中国企业的预算通常按年度规划，年初立项、年中执行、年底集中采购的节奏比较明显。很多企业在第四季度有"预算必须花完"的压力，也有一些企业在年初才开始讨论新的预算。营销和销售需要配合客户的预算节奏：上半年做认知和试点，下半年推动立项和采购。

**"AI 战略焦虑"**。2025 年以来，许多企业高层产生了强烈的"AI 战略焦虑"——担心在 AI 浪潮中落后于竞争对手。这种焦虑是推动采购的重要力量，但也可能导致"为了 AI 而 AI"的盲目项目。负责任的营销应该帮助客户把焦虑转化为清晰的落地路径，而不是利用焦虑卖出一个注定失败的项目。

## 3.6 政企与国央企：安全可控与示范效应

政企与国央企客户有其特殊性，我们将在第 12 章专门讨论。这里先概括它们的几个核心特征：

- **安全可控是第一要求**：数据不出域、私有化部署、国产化适配（信创）、等级保护等是基本门槛。
- **合规流程严格**：政府采购、招标投标、预算审批、"三重一大"决策等流程都需要遵守。
- **示范效应重要**：很多项目承担着示范、试点、标杆的功能，重视"可复制、可推广"。
- **决策周期长**：从接触到立项、招标、交付、验收，周期常常以年计。
- **生态合作普遍**：政企项目往往通过集成商、运营商、云厂商等伙伴来承接，Agent 厂商通常作为产品或技术提供方参与。

## 3.7 购买动机的四种类型

无论哪一层客户，购买 Agent 的动机大致可以归为四种类型。识别客户的主导动机，是制定营销信息的前提。

### 类型一：降本型

**核心诉求**：减少人力投入，降低运营成本。
**典型表述**："客服团队太大了""外包成本太高""招不到人"。
**营销信息重点**：可量化的成本节省、人员效率提升、规模化后的边际成本优势。
**注意事项**：降本型叙事容易引发员工的抵触情绪（"AI 来抢我的饭碗"）。在面对使用者时，应强调"把人从重复劳动中解放出来，去做更有价值的事"。

### 类型二：提效型

**核心诉求**：同样的人做更多的事，或者把事情做得更快、更好。
**典型表述**："研发交付太慢""响应客户需求不够快""报告做得太慢"。
**营销信息重点**：交付速度、产能提升、质量改善、员工满意度。
**注意事项**：效率提升的衡量往往比成本节省更难，需要帮助客户建立衡量指标（见第 16 章）。

### 类型三：创新与示范型

**核心诉求**：打造 AI 标杆项目，展示数字化转型成果，获得内外部认可。
**典型表述**："领导要求今年必须落地几个 AI 场景""我们要做行业首个 XX"。
**营销信息重点**：创新性、示范性、可展示性、可复制性、品牌影响力。
**注意事项**：这类项目往往有很强的展示需求，容易出现"演示很好、实际不用"的情况。要帮助客户把示范项目做成真正有价值的应用，否则下一年很难续约和扩张。

### 类型四：防御型

**核心诉求**：不想落后，不想被竞争对手甩开，不想在领导问起时无话可说。
**典型表述**："同行都在做，我们也得做""先试试看"。
**营销信息重点**：行业趋势、同行实践、低风险的起步方式、快速见效的试点方案。
**注意事项**：防御型客户购买意愿不够坚定，容易在试点阶段停滞。要尽快帮助他们找到真实的业务价值，把"防御"转化为"降本"或"提效"。

在实际销售中，客户往往同时具有多种动机，但通常会有一种主导动机。销售人员在第一次沟通中就应该通过提问识别主导动机，并据此调整沟通策略。

## 3.8 七大购买顾虑

如果说购买动机是油门，那么购买顾虑就是刹车。Agent 的营销和销售，很大程度上就是在帮客户松开刹车。根据大量企业沟通的经验，我们把客户的顾虑归纳为七类：

1. **数据安全顾虑**："我的数据会不会泄露？会不会被拿去训练模型？会不会出境？"
2. **效果不确定顾虑**："演示看起来很好，在我们的业务里真的能用吗？准确率有多高？"
3. **员工抵触顾虑**："员工会不会不愿意用？会不会引发裁员恐慌？"
4. **集成难度顾虑**："能和我们现有的系统打通吗？需要多少开发工作？"
5. **成本失控顾虑**："按用量计费，万一用超了怎么办？长期成本是多少？"
6. **责任归属顾虑**："Agent 做错了事，责任算谁的？造成损失怎么办？"
7. **供应商可持续性顾虑**："你们公司能活多久？技术路线会不会被淘汰？如果你们不做了，我们怎么办？"

这七大顾虑会在后面的章节中反复出现，并给出系统的应对方法。在这里先提供一个简单的原则：

> **每一个顾虑都应该有一份对应的"消除材料"**，并且在客户提出之前就主动提供。

比如，针对数据安全顾虑，准备数据流向说明和安全白皮书；针对效果不确定顾虑，准备同行业案例和 POC 方案；针对员工抵触顾虑，准备变革管理指南和员工培训方案；针对集成难度顾虑，准备集成清单和技术架构文档；针对成本失控顾虑，准备成本测算工具和用量上限设置说明；针对责任归属顾虑，准备人机协作流程设计和服务协议条款说明；针对供应商可持续性顾虑，准备公司介绍、融资与客户情况、数据迁移与退出方案。

## 3.9 Agent 购买旅程：比 SaaS 多出来的两站

传统 SaaS 的购买旅程通常是：**认知 → 兴趣 → 试用 → 评估 → 购买 → 使用 → 续费/扩张**。

Agent 的购买旅程在此基础上有两个关键变化：

**变化一：在"试用"和"评估"之间，多了一站"试点上岗"。**SaaS 的试用通常是用户自己点一点、看一看功能。Agent 的试用必须是在真实的业务环境中、处理真实的任务，才能证明价值。这意味着企业 Agent 的试用往往是一个有组织的试点项目（POC），需要接入数据、配置权限、设计流程、设定评估指标。

**变化二：在"购买"和"使用"之间，多了一站"规模化上岗"。**SaaS 签约后，用户开始使用就可以产生价值。Agent 签约后，还需要经历从试点到规模化的过程：扩大任务范围、增加使用人数、优化工作流程、建立人机协作机制。这个过程可能比试点本身更难，很多 Agent 项目就失败在这一步——试点效果很好，但无法规模化推广。

所以 Agent 的完整购买旅程是：

> **认知 → 兴趣 → 体验 → 试点上岗 → 评估 → 采购 → 规模化上岗 → 价值证明 → 续约与扩张**

我们把这个旅程称为 **"Agent 九站旅程"**。在后续章节中，我们会针对每一站讨论具体的营销和销售方法。

## 3.10 案例：一家制造企业的财务 Agent 采购之路

> 以下为综合化、匿名化案例，人名和公司名为化名，数字为示意。

华东某中型制造企业"恒达精工"有员工约一千二百人，年营收十余亿元，财务部门有二十多人。

**认知阶段**。2025 年春节后，公司董事长在一次行业协会的活动上听了一场关于 AI 在制造业应用的分享，回来后在管理层会议上提出："今年我们要在 AI 上做点事情。"信息中心主任王工被指定牵头调研。

**兴趣阶段**。王工在接下来的一个月里参加了三场 AI 主题的展会和峰会，看了十几家厂商的演示。他发现大多数演示都是"通用助手"式的问答，和公司业务关系不大。直到他在一个制造业数字化社群里看到一位同行分享："我们用 AI 智能体做供应商对账，财务部每月节省了大量人工。"他主动联系了这位同行，了解到对方使用的是一家专注于财务流程的 Agent 产品。

**体验阶段**。厂商的销售人员上门拜访，带来了一个用脱敏数据演示的对账 Agent：它能自动读取供应商发来的对账单（格式五花八门，有 Excel、PDF、扫描件），与公司 ERP 系统中的应付账款逐笔比对，标出差异并生成差异说明。财务总监李姐看完后说："演示是挺好，但我们的情况复杂得多。"

**试点上岗阶段**。厂商提出了一个为期六周的试点方案：选取二十家供应商的三个月对账数据，在客户的内网环境中部署，由财务部两名会计配合。试点的成功标准提前约定：差异识别准确率达到一定水平，单个供应商对账时间显著缩短。试点中遇到了很多问题：部分扫描件质量差、ERP 数据口径和供应商对账单口径不一致、有些差异需要结合采购合同才能判断。厂商的实施团队与财务人员一起，逐步完善了规则和流程。

**评估阶段**。试点结束时，结果基本达到了预期。但这时候，信息安全负责人提出了新的问题：Agent 是否会把财务数据传到外部？使用的是什么模型？是否满足公司的数据安全管理要求？厂商提供了私有化部署方案、数据流向说明以及模型来源说明，并安排技术专家与信息安全团队进行了两轮沟通。

**采购阶段**。项目进入采购流程。采购部门要求三家比价，财务部门要求明确未来三年的总成本。厂商提供了包含部署费、年度订阅费和实施服务费的报价，并承诺用量在一定范围内不额外收费，让财务部门能够做出准确预算。整个采购流程走了两个月。

**规模化上岗阶段**。正式上线后，对账 Agent 从二十家供应商扩展到全部三百多家供应商。厂商的客户成功团队每周与财务部开一次例会，跟踪问题、优化流程。三个月后，财务部的对账工作基本由 Agent 完成初步比对，会计只需要处理被标记的差异项。

**价值证明阶段**。年底，财务总监在公司年终总结会上汇报了对账 Agent 的成效：对账周期大幅缩短，差错率下降，两名会计被调整到更有价值的成本分析工作中。董事长在会上点名表扬，并要求信息中心探索 AI 在其他部门的应用。

**续约与扩张阶段**。第二年，恒达精工续签了对账 Agent，并新采购了发票审核 Agent 和费用报销审核 Agent。王工还在制造业数字化社群里分享了这个案例，为厂商带来了三家新的客户线索。

### 案例启示

这个案例展示了 Agent 九站旅程的完整过程，也体现了本章讨论的多个要点：

- **认知来自一把手**，而具体方案来自同行口碑。
- **演示无法打消"我们的情况更复杂"的顾虑**，只有在真实数据上的试点才能证明价值。
- **信息安全负责人在评估阶段出现**，如果没有提前准备好材料，项目可能在这里停滞。
- **财务部门关心成本的可预测性**，用量不封顶的计费方式会让他们难以预算。
- **规模化上岗需要持续的客户成功投入**，而不是签完合同就撤离。
- **价值证明的关键是让发起者在内部"有面子"**，财务总监在年终会上的汇报，是续约和扩张的直接推动力。
- **满意的客户会成为新的口碑来源**，形成增长飞轮。

## 本章要点

1. Agent 客户可以分为五层：政企与国央企、中大型企业、小团队与中小企业、专业个人、大众个人用户。不要同时攻打所有层级，选择一层切入，再向相邻层扩张。
2. 大众个人用户市场看起来最大，实际最难；专业个人（尤其是开发者）是当前 Agent 产品最重要的根据地；中小企业重"简单"；中大型企业是多角色的集体决策；政企重安全可控与示范效应。
3. 企业采购涉及发起者、使用者、决策者、把关者、采购者、财务六种角色。信息安全和法务往往拥有一票否决权，必须提前介入。
4. 购买动机分为降本型、提效型、创新与示范型、防御型四种，识别主导动机是制定营销信息的前提。
5. 客户有七大购买顾虑：数据安全、效果不确定、员工抵触、集成难度、成本失控、责任归属、供应商可持续性。每个顾虑都应有一份"消除材料"。
6. Agent 九站旅程：认知 → 兴趣 → 体验 → 试点上岗 → 评估 → 采购 → 规模化上岗 → 价值证明 → 续约与扩张。比 SaaS 多出了"试点上岗"和"规模化上岗"两站。
