# 第 15 章　客户成功：让 Agent 真正上岗并持续扩张

> 在 Agent 时代，客户成功团队的使命不是让客户"用起来"，而是让 Agent"干起来"。

## 15.1 Agent 时代客户成功的新使命

客户成功（Customer Success）是 SaaS 时代兴起的一个职能，其核心使命是确保客户通过使用产品获得预期的价值，从而实现续约和扩张。在 SaaS 模式下，客户的续费决策在很大程度上取决于他们是否从产品中获得了价值，因此客户成功成为了企业软件公司的核心能力。

在 Agent 时代，客户成功的重要性进一步提升，但使命也发生了变化。

**SaaS 时代的客户成功关注"采用"**：客户的员工有没有登录、有没有使用核心功能、使用的频次和深度如何。只要员工在用，就说明产品在产生价值。

**Agent 时代的客户成功关注"上岗"**：Agent 有没有在客户的业务中稳定地承担工作、完成了多少任务、完成的质量如何、为客户节省了多少时间和成本。员工登录产品只是手段，Agent 干活才是目的。

这个变化带来了一个有趣的视角：**Agent 的客户成功，很像是在管理一个"员工"的职业生涯**。一个新员工入职后，需要经历入职准备、试用期、转正、绩效考核、承担更多职责、晋升……Agent 在客户那里的"职业生涯"也是如此。客户成功团队的角色，就像是这个"员工"的职业导师和经纪人：帮助它顺利入职、通过试用、证明价值、获得更多的职责和信任。

## 15.2 Agent 在客户那里的"职业生涯"

我们把 Agent 在客户那里的生命周期，类比为一个员工的职业生涯，分为六个阶段：

### 阶段一：入职准备

就像新员工入职前需要准备工位、电脑、账号、入职材料一样，Agent 上岗前也需要准备：

- **知识准备**：Agent 需要了解客户的业务背景、流程规范、专业知识、历史经验。这些通常以知识库、项目说明文件、操作手册、案例库的形式提供给 Agent。
- **权限准备**：开通 Agent 需要访问的系统和数据的权限，按照最小权限原则配置。
- **流程准备**：设计 Agent 与人协作的工作流程：谁给 Agent 派活、Agent 的结果交给谁审核、出现问题找谁。
- **人员准备**：培训与 Agent 协作的员工，让他们了解 Agent 能做什么、如何派活、如何审核、如何反馈。

### 阶段二：试用期

新员工入职后通常有一个试用期，Agent 也一样。在试用期中：

- **从简单任务开始**：先让 Agent 处理简单、低风险的任务，逐步增加难度。
- **密切监督**：对 Agent 的工作结果进行全面审核，及时发现和纠正问题。
- **快速调整**：根据试用期的表现，调整 Agent 的知识、配置和工作流程。
- **记录表现**：系统地记录 Agent 的表现数据，为"转正"评估做准备。

### 阶段三：转正

试用期结束后，对 Agent 的表现进行评估。如果达到了预期的标准，Agent 正式"转正"，开始在业务中稳定承担工作。转正意味着：

- Agent 的工作范围和权限正式确定；
- 人工审核从全面审核转为抽检；
- Agent 的工作纳入正常的业务流程。

### 阶段四：绩效考核

就像员工需要定期进行绩效考核一样，Agent 也需要定期评估其工作表现：

- 完成了多少任务？
- 完成的质量如何？
- 为客户带来了多少价值？
- 有哪些需要改进的地方？

### 阶段五：扩岗与晋升

表现良好的员工会被赋予更多的职责，或者晋升到更高的岗位。Agent 也是如此：

- **扩岗**：承担更多类型的任务，服务更多的用户或部门。
- **晋升**：获得更高的自主程度，从"每一步都需要确认"到"自主完成，异常时请求介入"（见第 6 章的渐进式放权）。

### 阶段六：续约

在合同到期时，客户根据 Agent 的整体表现决定是否续约。如果前面五个阶段都做得好，续约就是水到渠成的事情。

### 用"员工"的语言与客户沟通

这个"职业生涯"的类比，不仅是一个内部的管理框架，也可以作为与客户沟通的语言。很多企业客户的管理者对"员工管理"非常熟悉，用"入职""试用期""转正""绩效考核""晋升"的语言来讨论 Agent，能够让他们迅速理解应该如何管理 Agent，也能让他们对 Agent 的发展有合理的预期。

比如，在项目启动会上，客户成功经理可以这样说："我们可以把这个 Agent 看作一位新同事。接下来的一个月是它的试用期，我们会一起观察它的表现，帮助它熟悉业务。试用期结束后，我们会进行一次'转正评估'，决定它正式承担哪些工作。"

## 15.3 入职准备：Agent 的"入职材料"

在 Agent 的职业生涯中，入职准备是最容易被忽视、却对后续表现影响最大的阶段。很多 Agent 项目效果不佳，根本原因是"入职材料"准备不足——Agent 不了解客户的业务，自然做不好工作。

### Agent 入职材料清单

| 材料类别 | 内容 | 示例（编程智能体） | 示例（客服智能体） |
|---|---|---|---|
| **背景介绍** | 业务背景、组织架构、关键术语 | 项目介绍、系统架构、技术栈说明 | 公司介绍、产品线介绍、服务政策 |
| **规范标准** | 工作规范、质量标准、格式要求 | 编码规范、提交规范、测试要求 | 服务话术规范、回复格式、禁用语 |
| **操作手册** | 常见任务的操作步骤 | 构建、测试、部署的命令 | 常见问题的处理流程 |
| **知识库** | 专业知识、历史经验 | 技术文档、设计文档 | 产品知识库、常见问题库 |
| **案例库** | 好的和不好的案例 | 优秀的代码示例、历史缺陷案例 | 优秀的服务案例、投诉案例 |
| **边界说明** | 不能做的事、需要上报的情况 | 不能修改的核心模块、需要人工评审的变更 | 需要转人工的情况、不能承诺的事项 |

### 帮助客户准备入职材料

很多客户并不清楚应该为 Agent 准备哪些材料，或者认为"AI 应该什么都知道"。客户成功团队需要主动帮助客户准备入职材料：

- **提供模板**：为不同类型的 Agent 提供入职材料模板，客户按照模板填写。
- **协助整理**：派遣顾问协助客户整理和组织已有的文档和知识。
- **自动提取**：利用 Agent 本身的能力，从客户已有的文档、代码、工单、聊天记录中自动提取和整理知识（在获得授权的前提下）。
- **持续迭代**：入职材料不是一次性的，需要根据 Agent 的表现持续补充和完善。

一个经验法则是：**Agent 的表现，有一半取决于模型能力，另一半取决于入职材料的质量。**在模型能力相同的情况下，入职材料准备充分的客户，Agent 的表现会好得多。

## 15.4 客户健康度评分

为了及时发现风险、把握机会，客户成功团队需要建立客户健康度评分体系，对每个客户的状况进行持续监控。

### Agent 客户健康度的维度

| 维度 | 指标 | 健康信号 | 风险信号 |
|---|---|---|---|
| **任务量** | 每周完成的任务数及趋势 | 稳定或增长 | 持续下降 |
| **任务质量** | 任务成功率、结果采纳率 | 高且稳定 | 下降或波动大 |
| **监督成本** | 人工审核和修改的时间 | 逐步下降 | 居高不下或上升 |
| **用户覆盖** | 使用 Agent 的用户数占目标用户的比例 | 逐步扩大 | 停滞或缩小 |
| **自主程度** | Agent 自主完成任务的比例 | 逐步提升 | 停滞或下降 |
| **自动化程度** | 定时任务、事件触发任务的比例 | 逐步提升 | 停滞 |
| **支持请求** | 问题和投诉的数量与严重程度 | 少且轻微 | 多或严重 |
| **关系深度** | 与客户决策者、发起者的关系 | 定期沟通，关系良好 | 联系人变动，沟通减少 |
| **满意度** | 净推荐值、满意度调研结果 | 高 | 低或下降 |
| **商业信号** | 预算、扩张意向 | 有扩张意向 | 预算削减、询问降级 |

### 红黄绿分级

根据各维度的综合得分，把客户分为三个等级：

- **绿色（健康）**：各项指标良好，客户满意，有扩张潜力。行动：寻找扩张机会，邀请成为案例和推荐者。
- **黄色（关注）**：部分指标出现风险信号。行动：深入了解原因，制定改进计划，增加沟通频次。
- **红色（风险）**：多项指标出现风险信号，存在流失风险。行动：立即升级处理，高层介入，制定挽回计划。

### 特别关注的风险信号

在所有风险信号中，有几个特别值得关注：

**发起者离职或调岗。**在中国企业中，人员变动是 Agent 项目最大的风险之一。当初推动项目的发起者离职或调岗后，新的负责人可能对项目缺乏了解和认同，项目可能被搁置甚至终止。一旦发现发起者变动，要立即与新负责人建立联系，重新证明价值。

**监督成本居高不下。**如果客户的员工需要花大量时间审核和修改 Agent 的结果，他们会逐渐失去耐心，认为"还不如自己干"。这是 Agent 项目失败的典型前兆。

**任务量突然下降。**任务量的突然下降，可能意味着出现了某个问题（比如 Agent 在某类任务上频繁出错），或者客户的业务发生了变化，需要及时了解原因。

## 15.5 价值证明：让价值被看见

Agent 为客户创造了价值，但如果这些价值没有被看见，客户在续约时就可能会犹豫。客户成功团队的一项核心任务，就是**让价值被看见**。

### 定期价值报告

定期（每月或每季度）向客户提供价值报告，内容包括：

- **工作量**：Agent 完成了多少任务，处理了多少数据。
- **效率**：节省了多少工时，缩短了多少周期。
- **质量**：任务的成功率、准确率，与人工相比的质量变化。
- **成本**：节省了多少成本，投资回报率是多少。
- **亮点**：Agent 在这一期间完成的特别有价值的工作，或者用户的正面反馈。
- **改进**：存在的问题和改进计划。
- **下一步**：下一阶段的目标和建议。

### Agent 绩效考核表

可以借用员工绩效考核的形式，为 Agent 制作一份"绩效考核表"。这种形式新颖有趣，便于客户的管理者理解，也便于在客户内部传播。

> **Agent 季度绩效考核表（示例）**
>
> 岗位：供应商对账专员
> 考核期：第三季度
>
> | 考核项 | 目标 | 实际 | 评价 |
> |---|---|---|---|
> | 完成对账的供应商数 | 300 家 | 326 家 | 超额完成 |
> | 差异识别准确率 | 95% | 97% | 达标 |
> | 平均对账周期 | 2 天 | 1.5 天 | 超额完成 |
> | 会计复核时间 | 每月 40 小时 | 每月 32 小时 | 达标 |
>
> 本季度亮点：发现了 3 起供应商重复开票的情况，避免了约 XX 万元的重复付款。
> 改进事项：部分扫描件识别准确率偏低，下季度将优化。
> 下季度目标：扩展到发票审核工作。

### 帮助发起者"向上汇报"

正如在第 3 章和第 11 章反复强调的，Agent 项目的发起者需要在内部证明项目的价值。客户成功团队应该帮助发起者准备向上汇报的材料：简洁的汇报 PPT、关键数据、成功故事、下一步的计划。当发起者在内部会议上自信地展示 Agent 的成果时，项目的续约和扩张就有了坚实的基础。

## 15.6 扩张：从一个岗位到一支团队

### 扩张的信号

客户成功团队要敏锐地捕捉扩张的信号：

- 客户在现有场景中的使用量持续增长，接近或超过合同额度；
- 客户询问 Agent 能否处理其他类型的任务；
- 其他部门的人员开始关注或尝试使用 Agent；
- 客户的发起者获得了内部的认可，有意愿推广到更多领域；
- 客户的业务规模扩大或有新的业务需求。

### 扩张的路径

在第 11 章，我们讨论了规模化的三个方向：横向扩展（更多用户）、纵向扩展（更多任务）、跨部门扩展（更多场景）。客户成功团队需要与客户共同规划扩张的路径，确保每一次扩张都有坚实的基础：

- **先巩固再扩张**：在现有场景稳定运行、价值得到证明之后，再考虑扩张。
- **复制成功经验**：把现有场景的成功经验（入职材料、工作流程、人员培训）复制到新的场景。
- **选择相邻场景**：优先扩张到与现有场景相邻的场景，这样可以复用知识和经验。

### 净收入留存

在 SaaS 行业，**净收入留存率**（Net Revenue Retention，NRR）是衡量客户成功效果的核心指标。它计算的是：一组客户在一年后的收入（包括续约、扩张、降级、流失的综合结果）与一年前收入的比值。NRR 超过 100%，意味着即使不获取新客户，来自老客户的收入也在增长。

对于 Agent 公司来说，NRR 尤其重要。因为 Agent 的价值是随着使用的深入而不断增长的：随着入职材料的完善、自主程度的提高、场景的扩展，Agent 能为客户做的事情越来越多，客户愿意支付的费用也越来越多。一个优秀的 Agent 公司，应该追求较高的 NRR。

## 15.7 续约管理

### 续约前九十天

续约不应该在合同到期前几天才开始考虑。建议在合同到期前九十天就启动续约管理：

- **到期前九十天**：评估客户健康度，识别风险；准备年度价值报告。
- **到期前六十天**：与客户的决策者进行年度业务回顾，展示价值，讨论下一年的计划；了解客户的预算情况。
- **到期前三十天**：提交续约方案和报价；处理客户的疑问和异议。
- **到期前**：完成续约合同的签订。

### 中国企业的续约特点

中国企业的续约有一些特点需要注意：

- **预算周期**：如果续约时间与客户的预算周期不匹配，可能出现"没有预算续约"的问题。要提前了解客户的预算周期，必要时调整合同周期。
- **重新采购**：部分企业——尤其是国企——在合同到期后需要重新走采购流程，不能直接续约。要提前了解客户的采购规定，做好重新参与采购的准备。
- **人员变动**：如前所述，人员变动是续约的重大风险。

## 15.8 Agent 特有的客户成功挑战

### 挑战一：模型升级管理

Agent 的底层模型会不断升级。模型升级通常会带来能力的提升，但也可能带来行为的变化：原来能正常完成的任务，在新模型下可能表现不同；原来的提示词和配置，在新模型下可能需要调整。

对于在客户业务中稳定运行的 Agent，模型升级需要谨慎管理：

- **提前通知**：在模型升级前通知客户，说明升级的内容和可能的影响。
- **回归测试**：在升级前，用客户的典型任务进行回归测试，确保关键任务的表现不下降。
- **灰度发布**：先在部分任务或部分用户中试用新模型，确认没有问题后再全面切换。
- **回退机制**：如果升级后出现问题，能够快速回退到原来的模型。
- **客户选择权**：对于企业客户，考虑提供选择权，让客户决定何时升级。

### 挑战二：效果漂移

即使模型没有变化，Agent 的效果也可能随着时间而下降，这被称为"效果漂移"。原因可能包括：

- 客户的业务发生了变化（新产品、新流程、新政策），而 Agent 的知识没有更新；
- 客户的数据格式或系统接口发生了变化；
- 任务的类型或难度发生了变化。

应对效果漂移，需要建立持续监控和定期维护的机制：监控 Agent 的关键指标，发现下降趋势时及时分析原因；定期与客户沟通业务变化，及时更新 Agent 的知识和配置。

### 挑战三：知识库维护

Agent 的入职材料和知识库需要持续维护。但在很多客户那里，知识库在项目初期建立后就没有人维护了，逐渐过时，导致 Agent 的表现下降。

客户成功团队需要帮助客户建立知识库的维护机制：明确知识库的负责人、建立更新流程、定期审核知识库的时效性。也可以利用 Agent 本身的能力，自动发现知识库中可能过时的内容，提醒客户更新。

## 15.9 客户成功团队的组织

### 分层服务模式

不同价值的客户，需要不同强度的客户成功服务。建议采用分层服务模式：

- **高触达**：针对高价值的大客户，配备专属的客户成功经理，提供深度的、个性化的服务，包括定期的现场拜访、业务回顾、高层对话。
- **中触达**：针对中等价值的客户，一个客户成功经理负责多个客户，提供定期的线上沟通和标准化的服务。
- **技术触达**：针对数量众多的小客户，主要通过自动化的方式提供服务：自动化的引导、自动化的健康度监控和提醒、在线知识库、社区支持、群组培训。

### 用 Agent 做客户成功

Agent 公司有一个独特的优势：可以用自己的 Agent 来做客户成功工作。比如：

- 自动生成客户的价值报告；
- 自动监控客户的健康度，发现风险时提醒客户成功经理；
- 自动回答客户的常见问题；
- 自动分析客户的使用数据，发现扩张机会。

这不仅能提高客户成功团队的效率，也是"吃自己的狗粮"的最佳实践，更是向客户展示 Agent 价值的生动案例。

## 15.10 从满意客户到品牌倡导者

客户成功的最高境界，是把满意的客户转化为**品牌倡导者**——愿意公开为你背书、向同行推荐你的客户。

在中国企业服务市场，客户倡导的力量尤其强大（见第 14 章）。客户倡导的形式包括：

- **客户案例**：授权公开发布的案例研究。
- **客户证言**：在官网、宣传资料、活动中使用的客户评价。
- **演讲分享**：在行业会议、你的用户大会上分享使用经验。
- **参访接待**：接待潜在客户参观交流。
- **推荐介绍**：向同行推荐你的产品。
- **媒体采访**：接受媒体关于 AI 应用的采访。

### 如何激励客户成为倡导者

- **让客户有面子**：客户的发起者在行业会议上分享成功经验，对他个人的职业发展也有帮助。为他创造这样的机会。
- **给客户实惠**：为倡导者提供一定的商务优惠、优先体验新功能等权益。
- **建立客户社区**：建立客户之间交流的社区，让客户在帮助他人的过程中获得成就感和影响力。
- **客户顾问委员会**：邀请最重要的客户加入客户顾问委员会，参与产品规划，让他们有参与感和归属感。

需要注意的是，在中国，部分企业——尤其是国企和金融机构——对公开宣传与供应商的合作比较谨慎，可能需要经过内部审批。要尊重客户的意愿，在获得正式授权之后再进行宣传。

## 15.11 案例：一个差点流失的客户

> 以下为综合化、匿名化案例，公司名为化名，数字为示意。

"博研智能"为一家大型连锁零售企业提供商品数据分析 Agent，帮助各区域的运营经理分析销售数据、发现问题、提出建议。项目上线后的前半年运行良好，客户健康度一直是绿色。

**风险出现**。上线第八个月，客户成功经理小陈发现了几个异常信号：每周完成的分析任务数量连续三周下降；部分区域的运营经理已经两周没有使用 Agent 了；客户的支持请求中出现了几条"分析结果不准确"的投诉。客户健康度从绿色变为黄色。

**深入调查**。小陈没有等待，立即展开调查。她与几位运营经理进行了电话沟通，很快找到了原因：客户在两个月前调整了商品分类体系，把原来的几百个品类重新划分。但 Agent 的知识库中仍然使用的是旧的分类体系，导致分析结果出现偏差。运营经理们发现分析结果不准确后，逐渐失去了信任，减少了使用。

更严重的是，小陈了解到，当初推动这个项目的客户方负责人——数字化部门的刘总——在一个月前调任到了其他部门，新的负责人对 Agent 项目并不了解，正在考虑"是否需要继续"。客户健康度变为红色。

**挽回行动**。小陈立即启动了挽回计划：

1. **快速修复**：协调技术团队，在一周内完成了知识库的更新，适配了新的商品分类体系；对已经产生的不准确分析，逐一进行了更正并通知相关的运营经理。
2. **高层介入**：安排博研的 CEO 与客户新的数字化负责人进行了一次会面，坦诚说明了问题的原因和处理措施，并汇报了项目上线以来的整体价值。
3. **价值重证**：准备了一份详细的价值报告，展示了 Agent 上线以来完成的分析任务数、发现的重要问题、带来的业务改善。
4. **机制完善**：与客户共同建立了"业务变更通知机制"——客户在发生重大业务变更（如分类调整、组织调整、系统升级）时，提前通知博研，博研及时更新 Agent 的知识和配置。
5. **重新培训**：为运营经理组织了一次重新培训，介绍了更新后的 Agent 和新增的功能。

**结果**。一个月后，Agent 的使用量恢复到了之前的水平。新的数字化负责人在了解了项目的价值之后，不仅决定续约，还提出要把 Agent 扩展到采购部门。这个差点流失的客户，最终成为了博研最大的客户之一。

### 案例启示

1. **客户健康度监控**能够帮助及早发现风险。
2. **效果漂移**是 Agent 特有的风险，业务变化会导致 Agent 的效果下降。
3. **发起者变动**是续约的重大风险，需要及时与新负责人建立关系。
4. **快速、坦诚的问题处理**能够挽回客户的信任。
5. **建立机制**比解决单次问题更重要，"业务变更通知机制"防止了类似问题再次发生。
6. **危机处理得当，可以转化为加深关系的机会。**

## 本章要点

1. Agent 时代客户成功的使命从"采用"变为"上岗"：关注 Agent 是否在客户业务中稳定承担工作。
2. Agent 在客户那里的"职业生涯"分为六个阶段：入职准备、试用期、转正、绩效考核、扩岗与晋升、续约。用"员工"的语言与客户沟通。
3. 入职准备是最容易被忽视、影响最大的阶段。Agent 的表现一半取决于模型能力，一半取决于入职材料的质量。
4. 建立客户健康度评分体系，特别关注发起者变动、监督成本居高不下、任务量突然下降等风险信号。
5. 让价值被看见：定期价值报告、Agent 绩效考核表、帮助发起者向上汇报。
6. 扩张要先巩固再扩张、复制成功经验、选择相邻场景。追求较高的净收入留存率。
7. 续约管理提前九十天启动，注意中国企业的预算周期、重新采购和人员变动。
8. Agent 特有的挑战：模型升级管理、效果漂移、知识库维护。
9. 分层服务模式，用 Agent 做客户成功。
10. 把满意的客户转化为品牌倡导者，尊重客户的宣传审批流程。
