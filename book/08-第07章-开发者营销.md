# 第 7 章　开发者营销：编程智能体的增长飞轮

> 对开发者做营销，最好的方式是让他们感觉不到你在做营销。

## 7.1 编程智能体：Agent 营销的"样板间"

在所有 Agent 品类中，编程智能体是最值得研究的一个。原因在第 1 章已经说过：代码是可验证的工作，编程智能体因此最先跑通了商业化。但对营销人来说，编程智能体还有另一层意义——**它是 Agent 营销的"样板间"**。

在这个样板间里，你可以看到 Agent 营销的几乎所有关键要素：

- **自下而上的扩散**：开发者个人先用起来，然后推荐给同事，再推动团队和公司采购。
- **口碑驱动的增长**：最有效的营销不是广告，而是开发者之间的口口相传。
- **产品即营销**：产品体验本身决定了传播效果，营销预算无法弥补产品体验的不足。
- **社区的力量**：开发者社区既是信息来源，也是信任来源。
- **从个人付费到企业采购的跃迁**：个人订阅到团队版、企业版的转化路径。

无论你的 Agent 是否面向开发者，研究编程智能体的增长方式都会给你带来启发。而如果你的 Agent 本身就面向开发者——编程智能体、Agent 开发平台、开发者工具——本章就是你的核心打法。

## 7.2 开发者的"反营销体质"

在开始讨论具体方法之前，必须先理解开发者这个群体的独特心理。我们把它概括为"**反营销体质**"。

### 特征一：天然怀疑一切宣传

开发者是一个高度理性、高度怀疑的群体。他们每天都在和"看起来能运行、实际上有 bug"的代码打交道，养成了"眼见为实、亲测为准"的习惯。任何夸张的宣传——"效率提升十倍""取代程序员"——都会立刻触发他们的怀疑。

### 特征二：只相信代码和同行

开发者最信任的信息来源有两个：**代码本身**和**同行的真实反馈**。一个开源项目的代码质量、一份清晰的技术文档、一位知名开发者的真实使用体验，比任何广告都有说服力。

### 特征三：高度重视自主选择权

开发者非常在意"我选择用什么工具"的自主权。被公司强制要求使用的工具，往往会遭到抵触；自己发现并喜欢上的工具，会主动向同事推荐。因此，即使你的目标是企业采购，也要先赢得开发者个人的认可。

### 特征四：对"恰饭"内容高度敏感

中国开发者社区对"恰饭"（收钱做推广）的内容非常敏感。一篇明显是软广的文章，即使内容不错，也可能在评论区被"围攻"。开发者希望看到的是真实、客观、有深度的内容，而不是包装精美的广告。

### 特征五：乐于分享，也乐于吐槽

开发者群体有很强的分享文化：分享好用的工具、分享踩过的坑、分享自己的项目。这意味着一个好产品可以通过开发者的自发分享快速传播；但同样，一个产品的缺陷也会被迅速放大。开发者的吐槽往往比赞美传播得更快。

### 应对之道：从"营销"到"服务"

理解了开发者的反营销体质，就能理解为什么传统的营销方法在开发者群体中效果不佳。对开发者做营销，核心思路是**从"营销"转向"服务"**：

- 不是告诉开发者"我们有多好"，而是帮助开发者"把事情做好"；
- 不是推销产品，而是提供价值——教程、工具、最佳实践、技术分享；
- 不是制造声量，而是赢得口碑；
- 不是追求曝光，而是追求真实使用。

## 7.3 编程智能体的增长飞轮

编程智能体的增长可以用一个飞轮来描述。理解这个飞轮，是制定开发者营销策略的基础。

### 飞轮的八个环节

1. **发现**：开发者通过同事推荐、社区讨论、技术文章、视频等途径知道了你的产品。
2. **尝试**：开发者安装产品，用它完成第一个任务。
3. **惊喜**：Agent 完成了一个让开发者惊喜的任务——"它居然自己把测试跑通了！"
4. **习惯**：开发者开始在日常工作中频繁使用 Agent，形成习惯。
5. **分享**：开发者在社区、社交媒体、同事之间分享自己的使用体验和技巧。
6. **团队扩散**：开发者推荐给团队中的同事，团队中越来越多的人开始使用。
7. **企业采购**：团队或公司决定统一采购，获得管理、安全和合规能力。
8. **产品改进**：更多的用户和收入带来更多的反馈和资源，产品变得更好，带来更多的惊喜，吸引更多的人发现和尝试。

这个飞轮一旦转起来，就会产生强大的自我强化效应。营销的任务，就是**找到飞轮中最薄弱的环节并加以强化**。

### 飞轮中最关键的两个环节

在这八个环节中，有两个环节是最关键的：

**环节三：惊喜。**如果开发者在尝试之后没有体验到惊喜，飞轮就会在这里停转。惊喜来自于 Agent 完成了一个开发者原本以为它做不到、或者需要花很多时间才能做到的任务。营销的任务是**帮助开发者尽快遇到惊喜**——通过快速上手指南、精选的入门任务、最佳实践分享，引导开发者用 Agent 去做它最擅长的事。

**环节五：分享。**惊喜如果没有被分享，就只是个人体验，无法推动飞轮。营销的任务是**降低分享的门槛、提高分享的意愿**——让 Agent 的工作成果易于分享，为分享者提供荣誉和激励，在社区中营造分享的氛围。

## 7.4 产品即营销：让产品本身成为传播载体

对于编程智能体来说，最好的营销是产品本身。以下是几个让产品成为传播载体的方法。

### 方法一：极致的安装与上手体验

开发者的耐心是有限的。如果安装过程复杂、配置繁琐、文档不清晰，很多开发者会在尝试阶段就放弃。好的编程智能体应该做到：

- **一行命令安装**：比如通过包管理器一行命令完成安装。
- **最少配置启动**：开箱即用，不需要复杂的配置就能开始第一个任务。
- **清晰的首次引导**：首次启动时，引导开发者完成登录、了解基本用法、尝试第一个任务。
- **国内网络友好**：在中国，安装和使用过程中的网络问题是一个常见的障碍。确保安装源、依赖下载、服务访问在国内网络环境下稳定可用，是国内产品相对海外产品的天然优势之一。

### 方法二：开源

开源是开发者营销最强大的武器之一。开源的好处包括：

- **建立信任**：开发者可以查看代码，了解工具在做什么，消除对安全和隐私的顾虑。
- **降低尝试门槛**：免费、可自由修改，开发者没有任何负担。
- **社区贡献**：开发者可以贡献代码、提出改进、开发插件，形成生态。
- **品牌影响力**：一个受欢迎的开源项目本身就是强大的品牌资产。

OpenAI 将其 Codex 命令行工具开源，就是利用开源来建立开发者信任和社区参与的例子。国内的大模型厂商也普遍通过开源模型来建设开发者生态。

开源策略需要仔细设计：开源什么、不开源什么，开源版本和商业版本如何区分，如何维护社区等。我们会在第 9 章详细讨论。

### 方法三：配置文件即传播

这是一个容易被忽视但非常有效的传播机制。

很多编程智能体支持在项目中放置一个说明文件（比如一些产品使用的项目级 Markdown 指令文件），用来告诉 Agent 这个项目的背景、规范、常用命令、注意事项。开发者会把这个文件提交到代码仓库中，以便团队中的其他人也能使用。

这个机制带来了一个意想不到的传播效果：**当一个开发者在项目中添加了这个文件，团队中的每一个人都会在代码仓库中看到它**。他们会好奇："这是什么？"然后去了解、尝试这个工具。说明文件成了产品在团队内部传播的"种子"。

更进一步，当开源项目中包含了这种说明文件，所有浏览这个开源项目的开发者都会看到它。这就形成了一种在开源社区中的自然传播。

营销启示：**设计让产品"留下痕迹"的机制**。编程智能体的提交信息、合并请求中的说明、生成的文档，都可以（在用户同意的前提下）包含产品的标识。这些痕迹会在团队协作和开源社区中被看到，形成自然的传播。但要注意分寸，过度的"品牌植入"会引起开发者的反感，务必默认克制并允许用户关闭。

### 方法四：可分享的工作成果

让 Agent 的工作成果易于分享：一个任务的完整执行记录可以生成一个分享链接；一次精彩的修复过程可以导出为动图或视频；一份 Agent 生成的技术报告可以一键分享到社区。降低分享的门槛，就能提高分享的频率。

## 7.5 文档即营销

对于开发者工具来说，**文档是最重要的营销资料之一**。很多开发者在决定是否尝试一个工具之前，会先看它的文档。文档的质量直接影响开发者对产品专业程度的判断。

### 好文档的五个层次

1. **快速开始**：五分钟之内，让开发者完成安装并跑通第一个任务。
2. **核心概念**：解释产品的核心概念和工作原理，帮助开发者建立正确的心智模型。
3. **使用指南**：针对常见场景，提供详细的使用说明和最佳实践。
4. **参考手册**：完整的命令、配置项、接口说明。
5. **实战案例库**：真实场景中的使用案例，包括任务描述、执行过程和结果。

### 中文文档的质量

对于面向中国开发者的产品，**中文文档的质量至关重要**。很多海外产品的中文文档是机器翻译的，读起来生硬拗口，甚至有错误。这是国内产品的机会：提供高质量的、原生的中文文档，用中国开发者熟悉的语言和例子来讲解。

但也要注意，很多中国开发者习惯阅读英文技术文档，尤其是在前沿技术领域。提供中英文双语文档，能够同时服务两类开发者，也有助于产品出海。

### 最佳实践是最好的营销内容

在文档中，最有营销价值的部分往往是"最佳实践"——如何写好任务描述、如何组织项目说明文件、如何在大型代码库中使用 Agent、如何把 Agent 集成到团队的开发流程中。

最佳实践内容有三个营销价值：

- 它帮助开发者更好地使用产品，提高完成率，增加惊喜；
- 它展示了团队的专业深度，建立信任；
- 它往往会被开发者转载和讨论，形成传播。

一些海外 AI 公司会定期发布关于如何构建 Agent、如何高效使用编程智能体的工程实践文章，这些文章在开发者社区中广受欢迎，被大量转载和讨论。这正是"内容即营销"在开发者群体中的典型体现。

## 7.6 开发者关系团队

如果你的产品面向开发者，建议组建专门的**开发者关系**（Developer Relations，简称 DevRel）团队。

### 开发者关系团队的职责

- **技术布道**：通过演讲、文章、视频、直播等方式，向开发者介绍产品和技术。
- **社区运营**：建设和维护开发者社区，回答问题，收集反馈，组织活动。
- **内容创作**：编写教程、最佳实践、案例分析等技术内容。
- **开发者体验**：从开发者的角度审视产品体验，推动产品改进。
- **生态建设**：与开源项目、技术社区、高校、合作伙伴建立联系。

### 开发者关系人员的素质

好的开发者关系人员需要同时具备三种素质：

1. **技术能力**：能够写代码，能够深入理解产品的技术细节，能够和开发者进行平等的技术交流。这是开发者关系人员赢得开发者信任的基础。
2. **表达能力**：能够把复杂的技术讲清楚，能够写出好的文章，能够做出精彩的演讲和视频。
3. **同理心**：能够站在开发者的角度思考问题，理解开发者的痛点和需求。

在中国，具备这三种素质的人才非常稀缺。一个可行的做法是：从公司内部的工程师中选拔有表达意愿和能力的人，给予时间和资源支持，让他们兼职或转岗做开发者关系工作。

### 开发者关系团队的考核

开发者关系团队的考核是一个难题。如果用销售额考核，他们会变成销售；如果只用声量考核，他们会追求虚荣指标。建议采用组合指标：

- **触达指标**：内容阅读量、活动参与人数、社区成员数。
- **激活指标**：通过开发者关系渠道带来的新用户数、首次任务完成数。
- **社区健康度**：社区活跃度、问题响应时间、用户自发分享数。
- **产品影响**：收集并推动解决的开发者反馈数量。
- **口碑指标**：开发者净推荐值、社区中的正面提及比例。

## 7.7 中国开发者渠道打法

中国开发者的信息获取渠道非常丰富，每个渠道有不同的特点和打法。

| 渠道 | 主要人群 | 内容形式 | 打法要点 |
|---|---|---|---|
| **GitHub / Gitee** | 全体开发者，开源爱好者 | 开源项目、示例代码 | 维护高质量的开源项目和示例仓库；及时响应问题和贡献 |
| **掘金** | 前端、移动端、全栈开发者 | 技术文章、专栏 | 发布实战教程和技术深度文章；参与平台的技术征文活动 |
| **CSDN** | 覆盖面最广，初中级开发者较多 | 技术博客、问答、下载 | 发布入门教程，覆盖搜索长尾流量 |
| **思否 / 开源中国 / 博客园** | 各类开发者，开源社区 | 技术文章、问答、开源资讯 | 发布技术文章，参与开源相关活动 |
| **V2EX** | 资深开发者、独立开发者 | 讨论帖 | 以个人身份真诚参与讨论；严禁硬广，会引起强烈反感 |
| **知乎** | 技术决策者、资深开发者 | 问答、专栏文章 | 回答相关技术问题，发布深度技术分析 |
| **B 站** | 年轻开发者、学生 | 技术视频、教程、实测 | 制作高质量教程视频和实测视频；与技术 UP 主合作 |
| **微信公众号** | 全体开发者，技术管理者 | 技术文章 | 运营官方技术号；与知名技术公众号合作 |
| **小红书** | 年轻开发者、产品经理、设计师 | 图文笔记、短视频 | 分享效率技巧、工具推荐；"AI 编程"相关话题热度高 |
| **即刻** | 科技圈早期用户、独立开发者 | 动态 | 创始人和团队成员个人账号运营，分享产品进展 |
| **技术社群** | 各类开发者 | 群聊 | 建立官方用户群，提供及时支持；在相关技术社群中提供价值 |
| **技术大会** | 技术决策者、资深开发者 | 演讲、展位 | 争取演讲机会，分享技术实践；赞助和展位作为补充 |
| **高校** | 学生、教师 | 讲座、课程、竞赛 | 教育优惠、校园大使、课程合作、赞助竞赛 |

### 渠道选择的原则

不要试图覆盖所有渠道。根据你的目标开发者群体，选择两到三个核心渠道深耕，其他渠道作为补充。比如，如果你的产品主要面向前端开发者，掘金、B 站、小红书可能是核心渠道；如果面向企业后端和架构师，知乎、微信公众号、技术大会可能更重要。

### 创始人和工程师的个人品牌

在开发者营销中，**个人的声音往往比官方的声音更有力量**。开发者更愿意听一位工程师分享真实的技术实践，而不是听官方账号发布产品公告。

鼓励创始人和核心工程师在社交媒体和技术社区建立个人品牌：分享技术思考、产品进展、踩过的坑、对行业的看法。这些个人内容会为产品带来真实可信的曝光。海外不少 AI 编程工具的创始人和工程师在社交媒体上都非常活跃，他们的个人分享往往比官方营销更受关注。

## 7.8 中国开发者的特殊情况

面向中国开发者做营销，还需要了解一些特殊情况，它们既是挑战，也是机会。

### 情况一：网络与访问

很多海外开发者工具在中国大陆的访问不稳定，加上海外头部模型厂商并未在中国大陆正式提供服务，中国开发者使用这些工具面临诸多障碍。这为国内的编程智能体提供了重要的市场空间。

**营销启示**：对于国内产品，"国内直接可用、稳定流畅"本身就是一个基础但重要的卖点。但不要把它作为核心卖点——如果你的产品只有"能用"这一个优势，一旦用户找到了其他途径，你就会失去他们。核心卖点仍然应该是产品本身的价值。

### 情况二：企业安全策略

很多中国企业出于安全考虑，禁止员工将公司代码上传到外部服务。这让开发者即使个人喜欢某个编程智能体，也无法在工作中使用。

**营销启示**：提供企业版、私有化部署版本、或基于企业自有模型的版本，是解决这个问题的关键。在营销中，要同时面向开发者（"你会喜欢它"）和企业安全负责人（"代码不出内网"）。

### 情况三：支付与报销

海外开发者工具通常需要用国际信用卡支付美元，这对很多中国开发者来说不方便，而且难以开具国内发票报销。

**营销启示**：支持微信支付、支付宝，能够开具增值税发票，支持企业对公转账，这些看似细节的能力，会显著影响付费转化率，尤其是团队和企业的采购。

### 情况四：本土技术栈

中国开发者的技术栈有一些本土特点：Java 在企业开发中占比很高；小程序开发是一个庞大的领域；鸿蒙应用开发正在快速兴起；国产数据库、国产中间件在政企项目中广泛使用；很多企业有大量基于国内开源框架的项目。

**营销启示**：针对本土技术栈做专门的优化和宣传，是国内编程智能体的重要差异化机会。比如"深度支持小程序开发""鸿蒙应用开发好帮手""熟悉国产数据库的 SQL 方言"等，这些都是海外产品难以覆盖的场景。

### 情况五：中文需求文档与中文注释

中国的开发团队大量使用中文撰写需求文档、技术文档、代码注释和提交信息。编程智能体对中文的理解能力和中文输出质量，直接影响使用体验。

**营销启示**：在演示和宣传中，使用中文需求、中文注释、中文交流的真实场景，让中国开发者看到"它懂我们的工作方式"。

## 7.9 从个人到团队到企业：自下而上的转化

编程智能体的典型增长路径是自下而上：从个人开发者开始，扩展到团队，最终进入企业采购。这个转化过程需要精心设计。

### 第一步：识别企业信号

在个人用户中，识别出可能转化为企业客户的信号：

- 同一企业邮箱域名下有多个用户注册；
- 某个用户的使用频次和深度明显高于平均水平；
- 用户在使用中连接了企业的代码仓库或内部系统；
- 用户咨询了团队版、企业版、发票、私有化部署等问题。

### 第二步：赋能内部倡导者

当识别到企业信号时，找到企业内部的"倡导者"——那个最早使用、最积极推荐的开发者。为他提供推动企业采购所需的"弹药"：

- **一页纸的产品介绍**：适合转发给技术负责人的简洁介绍。
- **效能数据报告**：基于他本人或团队的使用数据，展示 Agent 带来的效率提升。
- **安全合规资料**：给信息安全部门看的安全白皮书和数据流向说明。
- **团队试用方案**：一个低门槛的团队试用方案，让更多同事体验。
- **采购流程支持**：报价单、合同模板、资质文件，帮助他完成内部采购流程。

### 第三步：提供团队和企业能力

个人版和企业版的差异，不只是用量的差异，更重要的是管理和安全能力的差异：

- **统一管理**：管理员可以统一管理成员、分配权限、查看用量。
- **单点登录**：与企业的身份认证系统集成。
- **安全控制**：数据不用于训练的承诺、审计日志、访问控制、私有化部署选项。
- **效能度量**：团队级别的使用情况和效率提升数据，帮助技术管理者衡量投入产出。
- **统一计费**：统一付费、统一开票，方便企业财务管理。

### 第四步：向技术管理者证明价值

技术管理者最关心的问题是："这个工具真的让团队更高效了吗？投入值得吗？"

回答这个问题需要数据。但衡量研发效能是一个出了名的难题：代码行数不是好指标，提交次数不是好指标，"感觉更快了"也不是好指标。建议帮助技术管理者建立一套合理的衡量方法，比如：

- 需求从开始开发到上线的周期变化；
- 缺陷修复的平均时长变化；
- 单元测试覆盖率的变化；
- 开发者对工具的满意度和主观效率评价；
- Agent 完成并被合并的变更数量及其评审通过率。

我们会在第 16 章更详细地讨论度量问题。

## 7.10 开发者营销的度量

最后，讨论一下如何衡量开发者营销的效果。

### 警惕虚荣指标

开发者营销中最常见的虚荣指标包括：

- **开源项目的星标数**：星标数可以通过各种方式刷高，而且收藏不等于使用。
- **注册用户数**：注册了但从未使用的用户没有价值。
- **内容阅读量**：阅读了但没有尝试的读者没有转化。
- **社群成员数**：加群了但从不发言、从不使用的成员没有价值。

这些指标可以作为参考，但不应该作为核心考核指标。

### 核心指标

开发者营销的核心指标应该围绕"真实使用"：

- **激活率**：注册后完成第一个有效任务的用户比例。
- **周活跃用户**：每周至少使用一次的用户数。
- **任务完成数**：Agent 完成的任务总数，以及每用户平均任务数。
- **留存率**：第一周、第一个月、第三个月仍在使用的用户比例。
- **付费转化率**：免费用户转化为付费用户的比例。
- **团队渗透率**：企业客户中，使用产品的开发者占全部开发者的比例。
- **净推荐值**：开发者愿意向同事推荐产品的程度。
- **自发提及**：社区和社交媒体中，用户自发提及产品的数量和情感倾向。

## 7.11 案例：一款编程智能体的冷启动

> 以下为综合化、匿名化案例，公司名为化名，数字为示意。

"深码"是一款面向中国开发者的命令行编程智能体，由一支七人团队开发。团队没有营销预算，创始人决定用"开发者的方式"来做冷启动。

**第一阶段：种子用户（第 1–2 个月）**。创始人在即刻和 V2EX 上以个人身份发帖，真诚地介绍了团队在做的事情，坦白说明了产品目前的能力和局限，邀请感兴趣的开发者来试用并提意见。第一批约两百位种子用户加入了一个微信群。团队成员每天在群里回答问题、收集反馈，平均每两天发布一个新版本修复问题。种子用户感受到了"被重视"，其中一些人成为了产品最早的布道者。

**第二阶段：开源与内容（第 3–5 个月）**。团队把命令行客户端开源，并在 GitHub 和 Gitee 同步发布。同时，团队工程师开始在掘金和知乎上发布技术文章，主题包括"我们如何让 Agent 理解大型 Java 项目""编程智能体的上下文管理实践""为什么我们的 Agent 会先读测试再改代码"。这些文章没有一句广告，但每一篇都在讲产品背后的技术思考。其中一篇文章在掘金上获得了大量收藏和讨论，带来了一波用户增长。

**第三阶段：本土场景突破（第 6–8 个月）**。团队注意到，种子用户中有不少人在做小程序和鸿蒙应用开发，而这两个领域是海外编程工具覆盖较弱的。团队专门针对这两个领域做了优化，并发布了"用深码三十分钟开发一个鸿蒙应用"的 B 站视频教程。视频完整展示了从需求描述到应用运行的全过程，包括中间 Agent 犯错和自我修正的环节。这个视频在 B 站获得了较高的播放量，评论区里很多人说"终于有一个懂鸿蒙的 AI 编程工具了"。

**第四阶段：团队转化（第 9–12 个月）**。随着用户增长，团队发现有多家公司的开发者在同时使用深码。团队推出了团队版，提供统一管理、统一计费、增值税发票和使用数据看板，并为每个企业中最活跃的用户提供"内部推广包"。同时，团队推出了支持私有化部署的企业版，可以接入企业自有的模型服务。到第一年年底，深码获得了数十家付费企业客户。

### 案例启示

1. **创始人的真诚是冷启动最好的武器**。坦白说明局限，比夸大能力更能赢得开发者的信任。
2. **快速响应种子用户**，让他们感受到被重视，他们会成为最早的布道者。
3. **技术内容是开发者营销的核心**，讲清楚"为什么这样做"比讲"我们有多好"更有效。
4. **本土场景是国内产品的差异化机会**。
5. **诚实的演示**——包括犯错和修正——比完美的演示更有说服力。
6. **自下而上的转化需要主动设计**：识别企业信号、赋能内部倡导者、提供企业能力。

## 本章要点

1. 编程智能体是 Agent 营销的"样板间"，体现了自下而上扩散、口碑驱动、产品即营销等关键要素。
2. 开发者有"反营销体质"：怀疑宣传、相信代码和同行、重视自主选择、对"恰饭"敏感、乐于分享也乐于吐槽。核心思路是从"营销"转向"服务"。
3. 编程智能体的增长飞轮有八个环节：发现、尝试、惊喜、习惯、分享、团队扩散、企业采购、产品改进。最关键的是"惊喜"和"分享"。
4. 产品即营销：极致的安装体验、开源、配置文件即传播、可分享的工作成果。
5. 文档即营销：五个层次的文档，高质量的中文文档，最佳实践是最好的营销内容。
6. 组建开发者关系团队，用组合指标考核。
7. 中国开发者渠道丰富，选择两到三个核心渠道深耕；鼓励创始人和工程师建立个人品牌。
8. 中国开发者的特殊情况：网络访问、企业安全策略、支付与报销、本土技术栈、中文工作方式。
9. 自下而上转化四步：识别企业信号、赋能内部倡导者、提供团队和企业能力、向技术管理者证明价值。
10. 警惕虚荣指标，核心指标应围绕真实使用。
