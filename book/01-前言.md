# 前言　为什么"会干活的 AI"需要一本新的营销书

过去几年，几乎每一位做 AI 产品的人，都经历过同一种尴尬。

你把产品演示给客户看，客户眼睛一亮："哇，这个厉害。"然后呢？然后就没有然后了。客户回去以后，在群里转发了几次你的演示视频，说"AI 发展太快了"，但他的团队工作方式没有任何改变，他的采购预算里也没有你的名字。

在"聊天机器人"阶段，这种尴尬还可以用"市场教育尚未完成"来解释。但当产品进化到 Agent——也就是能够自己拆解任务、调用工具、操作软件、写代码、跑测试、交付成果的"会干活的 AI"——这种尴尬就变得更加刺眼了。因为 Agent 承诺的东西太具体了：它不是说"我能回答你的问题"，而是说"这件事我替你做完"。承诺越具体，客户的检验就越具体；客户的检验越具体，营销的难度就越大。

这本书就是为解决这个难题而写的。

## 一、Agent 改变了"卖软件"的底层逻辑

传统软件营销有一套成熟的方法：讲功能、讲场景、讲 ROI，然后试用、签约、续费。SaaS 时代又加上了产品驱动增长、客户成功、净收入留存这些概念。这些方法今天依然有用，但面对 Agent，它们都需要被重新校准。

原因在于，Agent 改变了软件和人之间的关系。

过去的软件是"工具"。工具不会自己动，用不用、怎么用、用得好不好，取决于人。所以软件营销的核心是**说服人去使用工具**。

Agent 是"同事"——至少它试图成为同事。同事是会自己动的。你给它一个目标，它自己想办法完成。于是营销的核心变成了**说服人把一件事托付出去**。

"使用"和"托付"是两种完全不同的心理。使用一个工具，最坏的结果是工具不好用，浪费了时间；托付一件事，最坏的结果是事情被搞砸了，而且是在你不知情的情况下被搞砸了。所以 Agent 营销的第一门槛不是"好不好用"，而是"敢不敢交"。

这个变化牵动了营销的每一个环节：

- **定位**要从"功能清单"变成"岗位说明书"——你的 Agent 到底能接手哪一个具体岗位的哪一部分工作？
- **定价**要从"按人头收费"变成"按工作量收费"甚至"按结果收费"——因为 Agent 越能干，需要的人头反而越少。
- **演示**要从"看我多聪明"变成"看我多靠谱"——客户想看的不是最惊艳的那一次，而是最普通的那一百次。
- **销售**要从"签单"变成"上岗"——合同签了只是开始，Agent 真正在客户的业务里稳定干活，才算成交。
- **品牌**要从"技术领先"变成"值得托付"——技术领先可以被追上，托付关系一旦建立却很难被替代。

## 二、中国市场让这一切变得更加独特

如果说 Agent 本身已经改写了营销逻辑，那么中国市场又在此基础上叠加了几层独特的地形。

第一层是**政策地形**。中国对生成式人工智能有一套相对完整、并且持续更新的监管框架：生成式人工智能服务管理办法、算法备案、深度合成管理、AI 生成内容标识、个人信息保护与数据安全，以及与数据出境相关的规定。对于营销团队来说，这不是法务部门的事情，而是会直接影响"你能对谁说什么、能怎么说、能在哪里说"的现实约束。

第二层是**生态地形**。中国的数字生态高度平台化：微信、抖音、小红书、知乎、B 站、钉钉、飞书、企业微信，每一个平台都有自己的规则、算法和用户心智。同时，国内大模型厂商之间的竞争异常激烈，价格战、开源战、生态战此起彼伏。一个 Agent 产品要在这片生态里找到自己的位置，既要借力平台，又要避免被平台吞没。

第三层是**客户地形**。中国企业的数字化水平参差不齐，从高度互联网化的科技公司，到仍以纸质流程为主的传统制造企业，再到对安全与自主可控有极高要求的国央企和政府机构，客户的需求、预算、决策方式差异巨大。私有化部署、信创适配、项目制交付、长决策链，这些都是中国企业服务市场的常态。

第四层是**心智地形**。中国用户对新技术的接受速度很快，但对付费软件的意愿相对谨慎；对"免费"高度敏感，对"效果"极其务实；容易被一个爆款演示点燃，也容易在一次翻车之后迅速冷却。

把这四层地形叠加在一起，你会发现：照搬硅谷的 Agent 营销方法在中国一定会水土不服，而照搬中国传统软件的营销方法又跟不上 Agent 的产品特性。我们需要一套专门的方法。

## 三、这本书写给谁

这本书写给所有在中国市场从事 AI Agent 相关工作的人，尤其是：

- **Agent 创业公司的创始人**。你需要知道在资源有限的情况下，先打哪个市场、先讲什么故事、先做哪些增长动作。
- **大模型厂商和云厂商的产品与市场团队**。你需要知道如何把模型能力包装成用户愿意付费的 Agent 产品，以及如何建设生态。
- **企业服务公司的销售与解决方案团队**。你需要知道如何把 Agent 卖进企业，如何设计 POC，如何应对采购与合规。
- **开发者关系与社区运营人员**。你需要知道如何在中国开发者群体中建立口碑，尤其是编程智能体这一最早跑通的品类。
- **出海与入华团队**。你需要知道海外 Agent 产品进入中国、中国 Agent 产品走向海外，分别需要跨越哪些障碍。
- **对 AI 商业化感兴趣的投资人、研究者和学生**。你可以从中看到这个产业在商业层面真正的难点。

## 四、这本书不是什么

为了避免误会，有几件事需要提前说明。

**这不是一本技术书。**书中会解释营销人必须懂的最小技术常识，但不会教你如何训练模型、如何写 Agent 框架。

**这不是一本产品评测书。**书中会以 Claude、Codex 等海外代表性产品，以及国内同类产品为参照来说明品类特征，但不会对任何产品做排名或推荐。AI 产品迭代速度极快，今天的功能对比，几个月后就可能失效。本书追求的是在产品快速迭代中依然成立的方法。

**这不是一本"AI 营销工具"书。**市面上有很多书在讲"如何用 AI 做营销"，比如用大模型写文案、做海报、剪视频。本书讨论的是另一个问题：**如何营销 AI 本身**，尤其是如何营销 Agent 这种新物种。当然，书中也会讨论如何让 Agent 参与到自己的营销中去——这本身就是最好的演示。

**这不是一本成功学。**Agent 行业还很年轻，很多问题没有标准答案。书中给出的框架是对当前实践的总结和推演，需要你结合自己的产品与市场去验证、修正。

## 五、贯穿全书的五个核心观点

在进入正文之前，先把全书最重要的五个观点列出来。如果你只有十分钟，读完这一节也会有收获。

**观点一：Agent 卖的是"被完成的工作"，不是"被提供的能力"。**客户不为模型参数付费，不为上下文长度付费，甚至不为"智能"付费，客户为"这件事我不用再操心了"付费。所有营销信息都应该从"完成了什么"出发，而不是从"具备什么"出发。

**观点二：可验证性决定了 Agent 的商业化速度。**编程智能体之所以最先跑出来，是因为代码的结果可以被测试、被编译、被评审——工作成果是可验证的。营销 Agent 的关键，就是帮客户找到"结果可验证"的任务，并把验证过程本身变成营销素材。

**观点三：信任是 Agent 的第一产品。**能力决定了 Agent 的上限，信任决定了 Agent 的下限。安全、合规、可控、可解释、可回滚，这些在传统软件里属于"非功能性需求"的东西，在 Agent 里是核心卖点。

**观点四：Agent 的成交发生在"上岗"，而不是"签约"。**Agent 的价值高度依赖于它在客户环境里的实际表现——数据接入、权限配置、流程改造、人员习惯。营销、销售和客户成功必须连成一条线，以"Agent 稳定干活"为终点来设计整个旅程。

**观点五：在中国，合规不是成本，而是护城河。**一个能清楚说明自己数据流向、模型来源、备案情况、内容标识方案的 Agent 产品，在企业客户和政企客户面前天然拥有信任溢价。越早把合规当作营销资产来经营，越能在竞争中占据主动。

## 六、如何使用这本书

全书分为四个部分，十九章，外加两个附录。

第一部分"认知篇"帮助你看清 Agent 这门生意：它是什么产品，中国市场有什么特点，客户是谁，他们怎么做购买决策。

第二部分"定位篇"帮助你在纷繁的竞争中站稳：如何定位、如何定价、如何把信任变成卖点。

第三部分"增长篇"是全书篇幅最大的部分，系统讨论开发者营销、内容营销、社区生态、产品驱动增长、企业销售、政企市场与渠道伙伴。

第四部分"品牌与长期篇"讨论如何做一家值得托付的 Agent 公司：品牌叙事、客户成功、度量体系、危机应对、跨境发展以及未来趋势。

附录 A 提供了可以直接使用的模板、清单与话术，附录 B 是术语表。

每一章结尾都有"本章要点"和"行动清单"。建议你读完一章后，花半小时对照自己的产品完成行动清单。营销是实践的学问，读一百个框架，不如在自己的产品上认真跑通一个。

最后，借用一句在 Agent 从业者之间流传的话作为开篇：

> **"用户不想要一个更聪明的 AI，用户想要一个更少让他操心的 AI。"**

让我们从这里出发。
