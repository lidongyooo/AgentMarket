# 第 9 章　社区与生态：开源、协议、插件与开发者大会

> 一个 Agent 能干多少活，不仅取决于它有多聪明，还取决于它能连接多少工具、多少数据、多少伙伴。

## 9.1 为什么 Agent 特别需要生态

在第 1 章，我们把 Agent 拆成了五个部分：模型、工具、记忆、规划和环境。其中，**工具**和**环境**在很大程度上不是由 Agent 厂商自己提供的，而是来自于外部的生态：企业的业务系统、第三方的 API、开源的工具库、各种数据源。

这意味着，Agent 的能力可以用一个简单的公式来表达：

> **Agent 的有效能力 ≈ 模型能力 × 可用工具 × 可用数据**

模型能力再强，如果不能连接客户的系统、访问客户的数据，也无法在客户的业务中干活。反过来，一个模型能力中等、但能连接大量工具和数据的 Agent，可能在实际业务中更有用。

这就是为什么生态对 Agent 特别重要。生态带来了三种价值：

**第一，能力扩展。**每增加一个工具连接器，Agent 就多了一种能力；每接入一个数据源，Agent 就多了一类可以处理的任务。生态越丰富，Agent 能干的活越多。

**第二，网络效应。**用户越多，开发者越愿意为这个平台开发工具和插件；工具和插件越多，平台对用户越有吸引力。这种正向循环一旦形成，就会构成强大的竞争壁垒。

**第三，信任传递。**当客户看到你的 Agent 已经与他们信任的系统和伙伴深度集成时，对你的信任也会增加。生态伙伴的背书，是主体可信的重要来源。

## 9.2 生态的四个圈层

Agent 的生态可以分为四个圈层，从内到外依次是：

1. **用户社区**：使用你的产品的个人和团队，他们分享经验、互相帮助、提供反馈。
2. **开发者与贡献者**：为你的产品开发插件、连接器、模板、扩展的开发者，以及为开源项目贡献代码的贡献者。
3. **合作伙伴**：与你的产品集成的软件厂商、提供数据和工具的服务商、帮助你销售和交付的渠道伙伴。
4. **行业与公共机构**：行业协会、标准化组织、研究机构、高校、政府部门。

每个圈层的建设方法不同，但它们相互关联：用户社区中的活跃用户可能成为开发者，开发者可能创办公司成为合作伙伴，合作伙伴可能参与行业标准的制定。

本章主要讨论前两个圈层和标准生态，合作伙伴中的渠道伙伴将在第 13 章专门讨论，政企相关的公共机构将在第 12 章讨论。

## 9.3 用户社区：中国式社群运营

### 中国用户社区的主要形态

与海外以论坛、Discord 为主的社区形态不同，中国的用户社区有其独特的形态：

- **微信群**：最普遍的社群形态。优点是触达率高、互动即时；缺点是信息容易被淹没、难以沉淀、群成员上限限制规模。
- **企业微信群 / 飞书群 / 钉钉群**：适合 B 端用户社群，便于企业身份识别和管理。
- **QQ 群**：在学生群体中仍然活跃。
- **官方论坛 / 社区网站**：便于内容沉淀和搜索，但活跃度通常不如即时通讯群。
- **知识星球等付费社群**：适合深度内容和高价值用户的运营。
- **Discord**：在开发者和出海产品中有一定使用，但在国内普及度有限。

很多 Agent 产品采用"**即时群 + 沉淀平台**"的组合：用微信群或企业微信群做即时互动和服务，用官方论坛或文档社区做内容沉淀和知识库。

### 社群分层运营

随着用户规模的增长，一个大群无法满足所有用户的需求。建议进行分层运营：

| 层级 | 对象 | 运营目标 | 运营方式 |
|---|---|---|---|
| **新手群** | 新注册用户 | 帮助快速上手，完成首次任务 | 入门教程、答疑、新手任务 |
| **用户群** | 一般活跃用户 | 提供支持，收集反馈 | 产品更新通知、问题解答、经验分享 |
| **场景群** | 特定场景的用户 | 深度交流，沉淀最佳实践 | 场景化分享、案例交流 |
| **核心用户群** | 高活跃、高贡献用户 | 共创产品，培养布道者 | 内测资格、产品共创会、专属权益 |
| **企业客户群** | 付费企业客户的对接人 | 服务保障，客户成功 | 专属服务、问题快速响应 |

### 超级用户计划

在每个社区中，都有一小部分特别活跃、特别热心的用户。他们使用产品最深入，乐于帮助他人，愿意分享经验。这些人是社区最宝贵的资产，我们称之为"**超级用户**"。

建立一个正式的超级用户计划（有些公司称之为"大使计划""布道师计划""KOC 计划"），给予他们：

- **认可**：专属的身份标识、官方的公开致谢、在社区中的特殊地位。
- **权益**：免费或优惠的高级套餐、新功能的优先体验、专属的周边礼品。
- **参与**：参与产品内测、参与产品共创会、与产品团队直接交流的机会。
- **成长**：分享和演讲的机会、内容创作的支持、个人品牌的曝光。

超级用户计划的关键是**真诚**。不要把超级用户当作免费的营销劳动力，而要真正尊重他们的贡献，让他们感受到被重视、有成长。

### 用户共创

Agent 产品特别适合用户共创。因为 Agent 的能力边界很大程度上是由用户的使用方式定义的，用户往往能够发现团队意想不到的使用场景和技巧。

用户共创的方式包括：

- **模板与工作流共创**：鼓励用户分享自己的任务描述模板、工作流配置，形成社区模板库。
- **场景征集**：定期征集用户的创新使用场景，优秀的场景可以被官方推广。
- **产品共创会**：邀请核心用户参与新功能的设计讨论。
- **问题共建**：用户提交的问题和解决方案，经过整理后进入官方知识库。

### 线下活动

在中国，线下活动对于建立深度的社区关系仍然非常重要。常见的形式包括：

- **城市 meetup**：在北京、上海、深圳、杭州、成都等城市定期举办用户交流活动。
- **工作坊**：手把手教用户使用 Agent 完成具体任务的实操活动。
- **用户大会**：一年一度的用户大会，集中展示产品进展、表彰优秀用户、分享案例。

线下活动的规模不需要很大，几十人的小型活动往往比几百人的大型活动更能建立深度连接。

## 9.4 开源策略

在第 7 章，我们提到开源是开发者营销最强大的武器之一。这里我们更系统地讨论 Agent 产品的开源策略。

### 开源什么

Agent 产品可以开源的部分包括：

- **客户端工具**：命令行工具、编辑器插件、桌面客户端。开源客户端可以消除用户对"它在我的电脑上做了什么"的顾虑。
- **SDK 与开发框架**：用于构建 Agent 的软件开发工具包和框架。开源 SDK 可以降低开发者的使用门槛，吸引开发者在你的平台上构建应用。
- **工具与连接器**：连接各种系统和服务的工具和连接器。开源连接器可以吸引社区贡献，快速扩展生态。
- **评测集与基准**：用于评估 Agent 能力的数据集和评测方法。开源评测可以建立行业话语权。
- **模型**：对于模型厂商来说，开源模型是建立开发者生态的核心手段。中国的大模型厂商在这方面非常积极，多个国产开源模型系列在全球开发者社区获得了广泛采用。

### 开源模式

常见的开源商业模式有三种：

**开放核心模式**：核心功能开源，高级功能（如企业级管理、安全、协作功能）收费。这是最常见的模式，平衡了社区吸引力和商业收入。

**开源 + 云服务模式**：软件完全开源，通过提供托管的云服务收费。用户可以自己部署开源版本，也可以付费使用省心的云服务。

**社区版 + 企业版模式**：提供功能有限的社区版（开源或免费）和功能完整的企业版（收费）。与开放核心模式类似，但两个版本可能是不同的代码库。

### 许可证选择

开源许可证的选择会影响社区的参与度和商业保护：

- **宽松许可证**（如 MIT、Apache 2.0）：允许他人自由使用、修改、商用。最有利于社区传播和采用，但对商业的保护最弱。
- **著佐权许可证**（如 GPL、AGPL）：要求衍生作品也必须开源。可以防止他人闭源商用，但会降低部分企业的采用意愿。
- **源码可用许可证**：源代码公开，但限制某些商业用途（比如禁止提供竞争性的云服务）。对商业的保护较强，但严格来说不属于开源，可能引起社区的争议。

对于大多数 Agent 产品的客户端和 SDK，建议使用宽松许可证，以最大化采用率。对于核心的平台软件，可以根据商业策略选择合适的许可证。

### 开源项目的运营

开源不是"把代码放到 GitHub 上"就结束了。一个成功的开源项目需要持续的运营：

- **高质量的说明文档**：中英文双语的说明，清楚地介绍项目是什么、怎么用、怎么贡献。
- **贡献指南**：明确的贡献流程和规范，降低贡献门槛。
- **及时的问题响应**：对用户提出的问题和贡献的代码及时响应。响应速度是开源项目健康度的重要指标。
- **规律的版本发布**：稳定的发布节奏，清晰的更新日志。
- **国内镜像**：在 Gitee 等国内平台同步发布，方便国内开发者访问。
- **社区治理**：随着项目的发展，建立清晰的社区治理机制，让社区成员有参与感。

### 开源的风险

开源也有风险，需要提前评估：

- **被大厂复制**：你的开源代码可能被资源更雄厚的大厂复制并改进，推出竞争产品。
- **维护负担**：开源项目需要持续投入维护，如果团队资源有限，可能难以为继。
- **商业转化困难**：如果开源版本过于完善，用户可能没有动力付费。
- **社区期望**：开源后再改变许可证或收回功能，会引起社区的强烈反弹。

## 9.5 协议与标准：在生态中找到你的位置

### 标准协议的意义

Agent 要连接各种工具和数据源，就需要有标准的连接方式。如果每个 Agent 都用自己的方式连接工具，每个工具都需要为每个 Agent 单独开发适配，整个生态的效率会非常低。

2024 年底，Anthropic 开源了模型上下文协议（MCP），试图为 AI 模型连接外部工具和数据源提供一个通用标准。这个协议此后获得了业界的广泛跟进，包括 OpenAI 在内的多家海外公司，以及国内众多的大模型厂商、云厂商、开发平台和工具厂商，都陆续宣布支持或兼容。此外，业界还出现了关于 Agent 之间相互通信与协作的协议探索。

标准协议的普及对 Agent 生态产生了深远影响：

- **降低了集成成本**：工具厂商只需要实现一次标准协议，就可以被所有支持该协议的 Agent 使用。
- **加速了生态繁荣**：大量的工具和数据源以标准协议的方式开放，Agent 能连接的范围迅速扩大。
- **改变了竞争格局**：当连接能力标准化之后，"能连接多少工具"不再是少数大厂的专属优势，小团队也能快速获得丰富的连接能力。

### 你的生态位策略

面对标准协议，Agent 厂商需要做出战略选择：

**策略一：拥抱标准。**全面支持主流的标准协议，让你的 Agent 可以使用生态中的所有工具，同时让你的工具可以被其他 Agent 使用。这是大多数 Agent 厂商的合理选择，因为它能以最低的成本获得最大的生态能力。

**营销表达**："支持 MCP 等主流协议，开箱即可连接数千种工具。"

**策略二：成为标准中的关键节点。**在标准协议的生态中，成为某一类工具或服务的最佳提供者。比如，成为"中国企业系统连接器"最全面的提供者，或者成为某个行业数据服务的标准接口。

**营销表达**："国内最全面的企业系统 MCP 连接器集合。"

**策略三：参与标准的制定。**参与国内外标准化组织、行业联盟关于 Agent 相关标准的制定工作。在中国，中国信息通信研究院等机构和各类行业联盟在推动 AI 相关标准和评估体系的建设，参与这些工作可以提升行业话语权，也能获得政企客户的认可。

**营销表达**："XX 标准参编单位。"

### 本土化的连接器机会

对于中国市场来说，有一个巨大的连接器机会：**中国本土的企业软件和服务**。海外的工具生态主要围绕海外的软件和服务构建，而中国企业使用的是另一套软件体系：

- 办公协同：钉钉、飞书、企业微信、WPS；
- 企业管理：用友、金蝶、浪潮等国产 ERP；
- 客户管理：各类国产 CRM 和 SCRM；
- 电商平台：淘宝天猫、京东、拼多多、抖音电商；
- 支付与财务：支付宝、微信支付、各类财税服务；
- 数据库与中间件：各类国产数据库和中间件；
- 政务系统：各类政务服务平台。

为这些本土系统构建高质量的连接器，是中国 Agent 厂商的重要机会。它既能增强自身产品的能力，也能成为生态中不可替代的节点。

## 9.6 插件、技能与连接器市场

很多 Agent 平台会建设一个市场（也被称为插件市场、技能市场、应用市场、连接器市场），让第三方开发者发布扩展能力，让用户发现和安装这些能力。

### 市场的冷启动

市场面临一个经典的"鸡生蛋"问题：没有足够的扩展，用户不会来；没有足够的用户，开发者不会来开发扩展。

破解冷启动的方法：

1. **官方先自建核心扩展**：在开放市场之前，官方先开发二三十个最常用、最高质量的核心扩展，确保用户一来就能找到有用的东西。
2. **邀请种子开发者**：邀请一批优质开发者和合作伙伴，在市场开放前完成扩展的开发，确保开放时有足够的内容。
3. **聚焦高价值场景**：不要追求扩展数量，而是确保高价值场景的扩展质量。十个精品扩展胜过一百个低质扩展。
4. **开发者激励**：为早期开发者提供流量扶持、现金激励、技术支持、联合营销等。

### 开发者激励机制

长期来看，市场的繁荣依赖于对开发者的持续激励：

- **收入分成**：允许开发者对扩展收费，平台与开发者分成。
- **流量扶持**：在市场首页、推荐位、官方内容中推荐优质扩展。
- **认证体系**：建立开发者和扩展的认证体系，认证扩展获得更高的信任和曝光。
- **技术支持**：提供完善的开发文档、示例代码、调试工具和技术支持。
- **社区荣誉**：评选优秀开发者和优秀扩展，给予公开表彰。

### 质量与安全审核

在第 6 章，我们提到了 Agent 的供应链风险：第三方扩展可能存在安全隐患。市场必须建立严格的质量与安全审核机制：

- **上架审核**：审查扩展的功能、权限申请、代码安全性。
- **权限透明**：清楚地向用户展示每个扩展需要哪些权限。
- **持续监控**：监控扩展的行为，发现异常及时处理。
- **企业管控**：允许企业管理员设置可用扩展的白名单。
- **问题响应**：建立用户举报和问题处理机制。

高质量的审核机制本身也是一个营销卖点："所有扩展都经过安全审核"能够让企业客户更放心。

## 9.7 开发者大会与黑客松

### 开发者大会

对于有一定规模的 Agent 平台来说，举办自己的开发者大会是建立生态影响力的重要方式。海外的 AI 公司普遍会举办年度开发者大会，发布重要产品和功能；国内的大厂和主要的 AI 公司也都有自己的开发者大会或年度发布会。

**自办大会的要点**：

- **有干货**：大会的核心是有价值的内容——重要的产品发布、深度的技术分享、真实的客户案例。没有干货的大会只是一场营销秀。
- **让开发者站上舞台**：邀请生态中的开发者和合作伙伴分享他们的实践，而不是只有官方的演讲。
- **动手环节**：设置工作坊和动手实验室，让参会者亲手体验新功能。
- **线上线下结合**：线下大会营造氛围和深度连接，线上直播扩大覆盖面。
- **持续的内容价值**：大会的演讲视频、资料、代码在会后持续发布，延长大会的影响力。

**参加他人大会的要点**：

如果自办大会的条件还不成熟，参加行业内的技术大会是很好的选择。国内有很多知名的技术大会和 AI 主题峰会，争取演讲机会比购买展位更有价值——一场有深度的技术演讲，能够带来比展位更多的关注和信任。

### 黑客松

黑客松（Hackathon）是一种非常适合 Agent 产品的社区活动形式：在限定的时间内（通常是一到两天），参与者组队使用你的产品和平台开发应用。

**黑客松的价值**：

- **激发创新**：参与者往往能开发出团队意想不到的创新应用。
- **培养开发者**：参与者在活动中深度学习和使用你的产品。
- **生成内容**：参赛作品是优质的案例和演示素材。
- **发现人才**：优秀的参与者可能成为你的员工、合作伙伴或核心用户。
- **建立品牌**：在开发者群体中建立积极的品牌形象。

**黑客松的设计要点**：

- **明确的主题**：围绕某个具体的场景或问题设定主题，比如"用 Agent 改造传统行业""Agent + 公益"。
- **充分的支持**：提供充足的算力额度、技术导师、开发文档和示例代码。
- **有吸引力的奖励**：奖金、算力额度、投资对接、孵化支持、工作机会。
- **后续的孵化**：为优秀作品提供后续的孵化支持，让好的创意能够落地。很多黑客松的问题在于"活动结束就结束了"。

### 高校合作

高校是开发者生态的源头。与高校的合作形式包括：

- **教育计划**：为学生和教师提供免费或优惠的产品使用权限。
- **课程合作**：与高校合作开设 AI Agent 相关的课程或实验，提供教学资源。
- **校园大使**：在高校招募校园大使，组织校园活动。
- **竞赛赞助**：赞助高校的编程竞赛、创新创业大赛。
- **联合研究**：与高校实验室开展联合研究项目。

高校合作的回报周期较长，但对于建立长期的开发者生态和品牌认知非常重要。今天的学生，就是几年后的开发者、技术负责人和采购决策者。

## 9.8 与大平台的竞合关系

在中国的 Agent 生态中，大平台（大模型厂商、云厂商、超级应用、办公协同平台、终端厂商）扮演着极其重要的角色。Agent 厂商与大平台之间，往往是一种复杂的竞合关系。

### 合作的机会

- **上架与入驻**：在大平台的应用市场、智能体商店、云市场上架你的产品。
- **技术集成**：与大平台的模型服务、开发平台、办公平台深度集成。
- **联合解决方案**：与大平台共同打造行业解决方案，共同拓展客户。
- **生态扶持计划**：参与大平台的生态伙伴计划，获得流量、资源和市场支持。

### 竞争的风险

- **平台自营**：大平台可能推出与你直接竞争的自有产品。
- **规则变化**：平台的规则、分成比例、推荐算法可能发生变化。
- **用户关系**：用户关系可能被平台掌握，你难以建立直接的用户关系。
- **依赖锁定**：过度依赖某个平台，会削弱你的议价能力。

### 竞合策略

- **多平台布局**：不要把所有的鸡蛋放在一个篮子里，同时与多个平台合作。
- **做平台不愿做的事**：专注于平台不愿意做、做不好或做不深的细分场景和行业。
- **保持核心资产独立**：核心技术、客户关系、数据资产要保持独立，不要完全依赖平台。
- **成为平台的优质伙伴**：如果你能为平台带来价值（比如丰富平台的生态、服务平台难以服务的客户），平台也会更愿意支持你。

## 9.9 生态健康度指标

如何衡量生态建设的效果？以下是一些关键指标：

**社区指标**：
- 社区活跃成员数（不是总成员数）
- 用户自发提问和回答的比例
- 问题平均响应时间
- 用户贡献的内容（模板、教程、案例）数量

**开发者指标**：
- 活跃开发者数量
- 第三方扩展数量和质量分布
- 扩展的安装量和使用量
- 开源项目的贡献者数量（不只是星标数）
- 开发者满意度

**伙伴指标**：
- 合作伙伴数量和活跃度
- 通过伙伴带来的客户和收入
- 联合解决方案的数量

**综合指标**：
- 用户使用的平均扩展数量（衡量生态对用户的价值）
- 使用扩展的用户留存率与不使用扩展的用户留存率对比（衡量生态对黏性的贡献）

## 9.10 案例：一个 Agent 平台的"百个连接器计划"

> 以下为综合化、匿名化案例，公司名为化名，数字为示意。

"织云"是一个面向企业的 Agent 开发与运行平台，帮助企业在内部构建和部署自己的 Agent。平台上线初期，团队发现了一个问题：企业客户在评估平台时，最常问的问题是"能连接我们的 XX 系统吗"。而当时平台只支持少数几个系统的连接，很多潜在客户因此流失。

团队决定启动"**百个连接器计划**"，目标是在六个月内上线一百个高质量的中国本土企业系统连接器。计划分为三个阶段：

**第一阶段：官方攻坚（第 1–2 个月）**。团队分析了潜在客户最常提及的系统，选出了三十个最高优先级的系统（包括主流的办公协同平台、国产 ERP、国产 CRM、主流国产数据库等），由官方团队开发连接器。所有连接器基于标准协议实现，同时兼容平台自身和其他支持该协议的 Agent。

**第二阶段：伙伴共建（第 3–4 个月）**。团队邀请了二十多家企业软件厂商和系统集成商参与共建。对于软件厂商，团队提供技术支持和联合营销，帮助他们以标准协议的方式开放自己的系统——这对软件厂商来说也是拥抱 AI 的一种方式。对于系统集成商，团队提供连接器开发的培训和认证，认证的连接器可以在平台市场上架，集成商可以通过连接器获得客户线索。

**第三阶段：社区开放（第 5–6 个月）**。团队开放了连接器开发框架和市场，举办了一场以"连接中国企业系统"为主题的线上黑客松，吸引了大量社区开发者参与。优秀的连接器经过审核后上架市场，开发者获得奖金和流量扶持。

六个月后，织云平台上的连接器数量超过了一百个，覆盖了中国企业最常用的大部分系统。这个成果带来了显著的商业效果：销售过程中"能不能连接"的问题大幅减少；多家软件厂商成为了织云的合作伙伴，在自己的客户中推荐织云平台；"国内连接器最全的 Agent 平台"成为了织云在市场上的一个鲜明标签。

更重要的是，由于连接器基于标准协议开发，它们也可以被其他支持该协议的 Agent 使用。这让织云在开发者社区中赢得了"开放"的声誉，吸引了更多开发者参与生态建设。

### 案例启示

1. **客户最常问的问题，就是生态建设的优先级**。
2. **官方先攻坚、伙伴共建、社区开放**是生态冷启动的有效路径。
3. **基于标准协议构建生态**，既能增强自身能力，又能赢得开放的声誉。
4. **为合作伙伴创造价值**，他们才会积极参与生态建设。
5. **本土化的生态能力**是中国 Agent 厂商的重要差异化来源。

## 本章要点

1. Agent 的有效能力 ≈ 模型能力 × 可用工具 × 可用数据。生态带来能力扩展、网络效应和信任传递。
2. 生态有四个圈层：用户社区、开发者与贡献者、合作伙伴、行业与公共机构。
3. 中国式社群运营采用"即时群 + 沉淀平台"组合，进行分层运营，建立真诚的超级用户计划，鼓励用户共创，重视线下活动。
4. 开源策略要明确开源什么、采用什么模式、选择什么许可证，并持续运营开源项目，同时评估开源风险。
5. 标准协议降低了集成成本、加速了生态繁荣。生态位策略包括拥抱标准、成为关键节点、参与标准制定。中国本土企业系统的连接器是重要机会。
6. 插件市场的冷启动：官方自建核心扩展、邀请种子开发者、聚焦高价值场景、开发者激励。必须建立严格的质量与安全审核。
7. 开发者大会要有干货、让开发者站上舞台；黑客松要有明确主题、充分支持和后续孵化；高校合作是长期投资。
8. 与大平台是竞合关系：多平台布局、做平台不愿做的事、保持核心资产独立、成为平台的优质伙伴。
