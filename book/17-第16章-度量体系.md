# 第 16 章　度量体系：Agent 产品的营销与增长指标

> 你无法管理你无法衡量的东西。但对于 Agent 来说，更危险的是衡量了错误的东西。

## 16.1 为什么 Agent 需要新的指标

互联网产品和 SaaS 产品已经形成了一套成熟的指标体系：日活跃用户、月活跃用户、留存率、付费转化率、客户获取成本、客户终身价值、年度经常性收入、净收入留存率……这些指标对于 Agent 产品仍然有参考价值，但它们有一个共同的局限：**它们衡量的是"人使用产品"，而 Agent 的价值在于"产品替人干活"。**

举一个简单的例子。在传统的互联网产品中，用户在产品中停留的时间越长，通常意味着产品越有价值。但对于 Agent 产品来说，情况恰恰相反：如果用户需要花很长时间与 Agent 交互、审核结果、纠正错误，这说明 Agent 的效率不高；理想的状态是，用户只需要花很少的时间交代任务和验收结果，Agent 就能把事情做完。

再比如，日活跃用户是互联网产品最重要的指标之一。但对于 Agent 产品来说，一个设置了定时任务的用户，可能一周才登录一次，但 Agent 每天都在为他干活。这个用户的"活跃度"很低，但价值很高。

因此，Agent 产品需要一套新的指标体系，能够准确地衡量 Agent 为用户创造的价值。

## 16.2 北极星指标

**北极星指标**是一个产品最核心的指标，它应该能够反映产品为用户创造的核心价值，并且与公司的长期商业成功高度相关。

对于 Agent 产品，我们推荐的北极星指标是：

> **每周被采纳的完成任务数**

拆解一下这个指标：

- **完成任务**：Agent 完成了任务，而不只是开始了任务。这反映了 Agent 的执行能力。
- **被采纳**：用户接受了 Agent 的结果——合并了代码、发送了邮件、使用了报告、确认了对账结果。这反映了 Agent 的工作质量。被拒绝或被大幅修改的结果不计入。
- **每周**：以周为单位，平滑日常的波动，反映持续的价值创造。

为什么不用"日活跃用户"或"任务总数"？

- **日活跃用户**衡量的是人的活跃，而不是 Agent 的价值。
- **任务总数**包含了失败的任务和不被采纳的任务，可能掩盖质量问题。一个 Agent 如果完成了大量任务但大部分都不被采纳，任务总数很高，但价值很低。

当然，不同类型的 Agent 可以根据自身特点调整北极星指标的定义。比如：

- 编程智能体：每周被合并的代码变更数；
- 客服智能体：每周独立解决的客户问题数；
- 财务智能体：每周完成并通过复核的单据数；
- 数据分析智能体：每周被使用的分析报告数。

关键是：**北极星指标应该衡量 Agent 交付的、被用户认可的工作成果。**

## 16.3 四层指标体系

在北极星指标之下，我们建议建立一个四层的指标体系：**获客层、激活层、价值层、商业层**。

### 第一层：获客层

获客层衡量的是营销的效果：有多少潜在用户知道并尝试了你的产品。

| 指标 | 定义 | 说明 |
|---|---|---|
| 访客数 | 访问官网、应用页面的独立访客数 | 按渠道细分 |
| 注册数 | 完成注册的用户数 | 按渠道细分 |
| 注册转化率 | 注册数 / 访客数 | 衡量官网和落地页的效果 |
| 线索数 | 企业客户的销售线索数 | 按来源细分 |
| 合格线索数 | 符合目标客户画像的线索数 | 衡量线索质量 |
| 客户获取成本 | 营销和销售总成本 / 新增付费客户数 | 按渠道和客户类型细分 |

### 第二层：激活层

激活层衡量的是新用户能否快速体验到 Agent 的价值。

| 指标 | 定义 | 说明 |
|---|---|---|
| 首次任务率 | 注册后一定时间内交代了首个任务的用户比例 | 衡量"空白输入框"问题 |
| 首个完成任务率 | 注册后一定时间内完成首个任务并采纳结果的用户比例 | Agent PLG 的核心激活指标（见第 10 章） |
| 首次价值时间 | 从注册到首个完成任务的时间 | 越短越好 |
| 首次成功率 | 首个任务被成功完成并采纳的比例 | 衡量首次体验的质量 |

### 第三层：价值层

价值层是 Agent 产品最独特、最重要的一层，衡量的是 Agent 为用户创造的实际价值。

| 指标 | 定义 | 说明 |
|---|---|---|
| 任务完成率 | 成功完成的任务数 / 交代的任务数 | 衡量 Agent 的执行能力 |
| 采纳率 | 被采纳的任务数 / 完成的任务数 | 衡量 Agent 的工作质量 |
| 修改率 | 采纳前需要人工修改的任务比例，以及修改的程度 | 衡量结果的直接可用性 |
| 监督时间 | 用户在交代任务、审核结果、纠正错误上花费的时间 | 衡量监督成本 |
| 节省工时 | Agent 完成的工作如果由人完成需要的时间 − 监督时间 | 衡量净价值 |
| 自主度 | Agent 无需人工介入独立完成的任务比例 | 衡量信任程度和放权程度 |
| 自动任务占比 | 定时任务、事件触发任务在全部任务中的比例 | 衡量 Agent 融入工作流的程度 |
| 任务复杂度分布 | 不同复杂度任务的分布 | 衡量用户托付的工作深度 |
| 留存率 | 一定时间后仍在使用的用户或客户比例 | 按周、月、季度计算 |

### 第四层：商业层

商业层衡量的是公司的商业健康度。

| 指标 | 定义 | 说明 |
|---|---|---|
| 付费转化率 | 付费用户数 / 注册用户数 | 按渠道和用户类型细分 |
| 每用户平均收入 | 总收入 / 付费用户数 | 衡量变现能力 |
| 毛利率 | （收入 − 直接成本）/ 收入 | Agent 产品要特别关注推理成本 |
| 单位任务成本 | 完成一个任务的平均直接成本 | 看分布，不只看平均 |
| 年度经常性收入 | 订阅类收入的年化值 | 衡量收入规模 |
| 净收入留存率 | 老客户一年后收入 / 一年前收入 | 衡量扩张与流失的综合效果 |
| 总收入留存率 | 老客户一年后收入（不含扩张）/ 一年前收入 | 衡量流失和降级 |
| 客户终身价值与获客成本比 | 客户终身价值 / 客户获取成本 | 衡量获客的经济效益 |
| 获客成本回收期 | 收回获客成本所需的月数 | 衡量资金效率 |

## 16.4 Agent 特有指标详解

在上面的指标中，有几个是 Agent 产品特有的，值得详细讨论。

### 采纳率与修改率

**采纳率**和**修改率**是衡量 Agent 工作质量最直接的指标。

采纳率的计算需要定义"采纳"。不同的 Agent 产品有不同的定义方式：

- 编程智能体：代码变更被合并到代码库；
- 写作智能体：生成的内容被用户保存或发布；
- 客服智能体：回复被发送给客户，且客户没有要求转人工；
- 分析智能体：报告被用户查看、下载或分享。

修改率衡量的是用户在采纳前对 Agent 结果进行了多少修改。可以通过比较 Agent 的原始输出和用户最终采纳的版本来计算。修改率越低，说明 Agent 的结果越直接可用，监督成本越低。

### 监督时间

**监督时间**是第 1 章净交付价值公式中"监督成本"的直接体现。它衡量的是用户为了让 Agent 完成任务而花费的时间，包括：

- 交代任务的时间；
- 回答 Agent 澄清问题的时间；
- 审核结果的时间；
- 纠正错误和补充完成的时间。

监督时间可以通过产品内的行为数据来估算（比如用户在审核界面停留的时间、修改的操作次数），也可以通过用户调研来了解。

一个健康的 Agent 产品，**监督时间应该随着使用的深入而逐步下降**：用户学会了更好地交代任务，Agent 积累了更多的上下文，入职材料逐步完善，自主程度逐步提高。如果监督时间居高不下或持续上升，是一个严重的风险信号。

### 单位任务成本与毛利率

在第 5 章，我们讨论了 Agent 产品的成本结构：每一个任务都在消耗算力。**单位任务成本**和**毛利率**是 Agent 公司必须密切关注的商业指标。

需要特别注意以下几点：

- **看分布，不只看平均**：如前所述，Agent 任务的成本呈现长尾分布。要关注高成本任务的比例和特征。
- **按用户类型分析**：不同类型的用户（免费用户、付费用户、重度用户）的成本差异很大。
- **跟踪趋势**：随着模型价格的下降和工程优化，单位任务成本应该逐步下降。如果单位任务成本上升，要分析原因——是任务变得更复杂了，还是出现了效率问题？
- **毛利率与 SaaS 的对比**：传统 SaaS 公司的毛利率通常较高，而 Agent 公司由于推理成本的存在，毛利率可能明显低于传统 SaaS。投资人和管理层需要对此有合理的预期，同时公司要有清晰的毛利率提升路径。

## 16.5 如何衡量给客户的价值

在企业销售和客户成功中，我们反复强调要"让价值被看见"。但衡量 Agent 为客户创造的价值，本身就是一个难题。

### 节省工时的测量方法

"节省了多少工时"是最常用的价值指标，但也是最容易被夸大的指标。以下是几种测量方法，按照可信度从高到低排列：

**方法一：基线对比。**在引入 Agent 之前，测量完成某类任务的平均耗时（基线）；引入 Agent 之后，再测量同类任务的平均耗时（包括监督时间）。两者的差值就是节省的工时。这是最可信的方法，但需要在项目开始前就规划好基线测量。

**方法二：抽样计时。**随机抽取一部分任务，由人工完成并记录耗时，与 Agent 完成的同类任务（包括监督时间）进行对比。

**方法三：用户自报加校准。**请用户估计"如果没有 Agent，完成这个任务需要多长时间"，同时用其他方法进行校准。用户自报的数据往往会偏高，需要谨慎使用。

**方法四：任务量推算。**根据 Agent 完成的任务量和人工完成同类任务的标准耗时，推算节省的工时。这是最简单的方法，但可信度最低，因为它没有扣除监督时间，也没有考虑任务难度的差异。

### 不要夸大价值

在价值衡量中，有一个强烈的诱惑：夸大 Agent 的价值，让数字看起来更漂亮。但夸大的价值会带来严重的后果：

- **客户不信任**：客户的员工最清楚 Agent 实际节省了多少时间。如果价值报告中的数字与他们的感受差距很大，他们会对整个报告失去信任。
- **期望失控**：夸大的价值会推高客户的期望，下一次就更难满足。
- **违反法规**：在公开宣传中使用夸大的数据，可能违反广告法。

**建议：宁可保守，不要夸大。**在价值报告中说明测量方法和局限，使用保守的估算。一份诚实的价值报告，比一份夸大的价值报告更有说服力。

### 超越工时：多维度的价值

节省工时只是 Agent 价值的一个维度。还应该关注其他维度的价值：

- **质量价值**：错误率的降低、一致性的提高、合规性的改善。
- **速度价值**：周期的缩短、响应时间的缩短。
- **规模价值**：处理能力的提升，能够处理以前无法处理的任务量。
- **体验价值**：员工满意度的提升、客户满意度的提升。
- **业务价值**：收入的增长、成本的节省、风险的降低。

## 16.6 编程智能体的效能度量

编程智能体的价值度量是一个特别受关注的话题。技术管理者在决定是否为团队采购编程智能体时，最常问的问题就是："它到底能让团队效率提升多少？"

### 不要用代码行数

一个常见的错误是用"Agent 生成的代码行数"或"AI 生成代码的占比"来衡量编程智能体的价值。这种指标有很大的问题：

- 代码行数不等于价值，更多的代码可能意味着更多的维护负担；
- 生成的代码可能被大量修改甚至删除；
- 容易被操纵和误解。

### 推荐的效能指标

更好的做法是关注软件交付的整体效能。业界广泛使用的软件交付效能指标包括：

- **变更前置时间**：从代码提交到部署上线的时间。
- **部署频率**：团队多久部署一次。
- **变更失败率**：部署后导致故障的变更比例。
- **故障恢复时间**：从故障发生到恢复的时间。

此外，还可以关注：

- **需求交付周期**：从需求确认到上线的时间。
- **合并请求周期**：从创建合并请求到合并的时间。
- **评审一次通过率**：Agent 提交的变更在评审中一次通过的比例。
- **缺陷修复时间**：从缺陷报告到修复的时间。
- **测试覆盖率**：单元测试覆盖率的变化。
- **开发者体验**：通过定期调研了解开发者对工具的满意度、主观效率感受、工作满意度。

### 度量的注意事项

- **对比要公平**：比较引入编程智能体前后的效能时，要考虑团队规模、项目类型、业务复杂度等因素的变化。
- **关注团队而非个人**：效能度量应该关注团队整体，而不是用来考核个人。用编程智能体的使用数据来考核开发者个人，会引发反感和数据造假。
- **给予时间**：开发者需要一段时间来学习和适应编程智能体，效能的提升可能需要几个月才能显现。

## 16.7 营销归因：中国市场的特殊挑战

### 归因的难题

营销归因是指判断一个客户是通过哪个营销渠道或营销活动获得的。准确的归因对于优化营销投入至关重要。

但在中国市场，营销归因面临特殊的挑战：

- **私域流量**：大量的传播发生在微信群、朋友圈、私聊中，这些渠道的传播路径很难追踪。
- **跨平台传播**：用户可能在抖音看到短视频，在小红书搜索评价，在知乎看深度分析，在微信群里问朋友意见，最后在官网注册。多个触点的贡献很难区分。
- **线下影响**：行业会议、同行交流、客户推荐等线下影响，很难被数据记录。
- **企业决策**：企业客户的决策涉及多个角色，每个角色可能通过不同的渠道了解你的产品。

这些难以追踪的流量，被称为"**暗流量**"。在中国的企业服务市场，暗流量的比例可能相当高。

### 应对方法

**方法一：自报归因。**在注册表单、销售线索表单中，增加一个简单的问题："你是怎么知道我们的？"提供选项（同事或朋友推荐、搜索引擎、技术社区、短视频、公众号文章、行业会议等），同时允许用户自由填写。自报归因虽然不完美，但往往能揭示数据追踪无法发现的真实来源——很多公司会惊讶地发现，"朋友推荐"是最大的来源。

**方法二：销售访谈。**在销售过程中，询问客户是如何了解到你的产品的，以及在决策过程中参考了哪些信息。

**方法三：渠道专属标识。**在不同的渠道使用专属的链接、二维码、邀请码、优惠码，以便追踪来源。

**方法四：增量实验。**在某个渠道暂停或增加投入，观察整体获客的变化，判断该渠道的增量贡献。

**方法五：接受不确定性。**承认归因无法做到完全精确，用多种方法相互印证，形成合理的判断，而不是追求虚假的精确。

## 16.8 仪表盘设计

建议为不同的角色设计不同的仪表盘：

### 管理层仪表盘

关注公司整体的健康度：

- 北极星指标及趋势
- 收入（年度经常性收入、新增、扩张、流失）
- 毛利率及单位任务成本趋势
- 净收入留存率
- 客户获取成本与回收期
- 现金流

### 营销仪表盘

关注获客和激活：

- 各渠道的访客、注册、线索及趋势
- 各渠道的客户获取成本
- 自报归因的分布
- 首次任务率、首个完成任务率
- 内容表现（阅读、互动、转化）

### 产品与增长仪表盘

关注激活和价值：

- 激活漏斗各环节的转化率
- 任务完成率、采纳率、修改率
- 监督时间趋势
- 自主度、自动任务占比
- 留存曲线

### 客户成功仪表盘

关注客户健康度：

- 客户健康度分布（红黄绿）
- 风险客户清单及原因
- 扩张机会清单
- 即将到期的合同及续约状态
- 净收入留存率、总收入留存率

## 16.9 指标的陷阱

### 陷阱一：虚荣指标

虚荣指标是那些看起来很漂亮、但与真实价值关系不大的指标，比如注册用户总数、累计任务数、开源项目星标数、社群总人数。它们可以用来对外宣传，但不应该用来指导决策。

### 陷阱二：古德哈特定律

经济学中有一个著名的古德哈特定律："当一个指标变成目标时，它就不再是一个好的指标。"当团队被某个指标考核时，他们可能会想办法提高这个指标，而不是提高指标背后的真实价值。

比如，如果用"任务完成数"考核产品团队，团队可能会鼓励用户把大任务拆成很多小任务；如果用"采纳率"考核，团队可能会让 Agent 只接受简单的任务。

**应对**：使用多个相互制衡的指标；定期审视指标是否仍然反映真实价值；在考核中结合定性的判断。

### 陷阱三：只看平均

平均值会掩盖很多重要的信息。比如，平均任务完成率 80%，可能是所有用户都在 80% 左右，也可能是一半用户 100%、一半用户 60%。后者意味着有一半的用户体验很差，可能正在流失。

**应对**：关注分布，按用户类型、任务类型、渠道等维度细分分析。

### 陷阱四：忽视成本

有些团队只关注增长指标，而忽视了成本指标。在 Agent 产品中，增长往往伴随着成本的增长，如果只看增长不看成本，可能会出现"增长越快、亏损越大"的情况。

**应对**：把单位经济指标（单位任务成本、毛利率、客户获取成本回收期）纳入核心关注。

## 16.10 案例：一次北极星指标的调整

> 以下为综合化、匿名化案例，公司名为化名，数字为示意。

"笔耕智能"是一家写作 Agent 公司，帮助用户撰写各类文档：营销文案、工作报告、商业计划书等。公司成立初期，把"每日活跃用户数"作为北极星指标，所有团队都围绕这个指标工作。

在这个指标的驱动下，团队做了很多提升活跃度的工作：每日签到奖励、每日写作挑战、推送提醒、社交功能……日活跃用户数稳步增长，团队很满意。

但财务部门发现了一个问题：虽然日活跃用户在增长，付费转化率却在下降，续费率也不理想。进一步分析发现，很多"活跃用户"是被签到奖励和写作挑战吸引来的，他们使用产品的目的是"玩"而不是"工作"，生成的内容大多不会被实际使用。而真正的付费用户——那些用产品写工作文档的职场人士——他们的需求被忽视了：产品团队把大量精力投入到提升活跃度的功能上，而写作质量、文档格式、与办公软件的集成等核心需求进展缓慢。

公司管理层意识到北极星指标出了问题，决定进行调整。新的北极星指标是：**每周被导出或分享的文档数**——只有被用户导出到办公软件或分享给他人的文档，才被认为是"被采纳"的工作成果。

指标调整后，团队的工作重心发生了显著变化：

- 产品团队开始重点提升写作质量和文档格式；
- 增长团队开始重点获取职场用户，而不是泛娱乐用户；
- 市场团队开始重点宣传"写出能直接用的文档"，而不是"有趣的 AI 写作"；
- 签到奖励等提升虚假活跃度的功能被逐步下线。

半年后，日活跃用户数有所下降，但每周被导出或分享的文档数显著增长，付费转化率和续费率都有了明显提升，公司的收入和毛利率也有了改善。

### 案例启示

1. **北极星指标决定了团队的工作方向**，选错了指标会让团队朝错误的方向努力。
2. **活跃度不等于价值**，对于 Agent 产品尤其如此。
3. **"被采纳的工作成果"**是 Agent 产品更好的北极星指标。
4. **调整指标需要勇气**，可能意味着某些数字的下降，但长期来看是值得的。

## 本章要点

1. 传统指标衡量的是"人使用产品"，Agent 的价值在于"产品替人干活"，需要新的指标体系。
2. 推荐的北极星指标是"每周被采纳的完成任务数"，衡量 Agent 交付的、被用户认可的工作成果。
3. 四层指标体系：获客层、激活层、价值层、商业层。价值层是 Agent 产品最独特、最重要的一层。
4. Agent 特有指标：采纳率与修改率衡量工作质量；监督时间应随使用深入而下降；单位任务成本与毛利率要看分布、跟踪趋势。
5. 衡量客户价值：基线对比最可信；宁可保守，不要夸大；关注质量、速度、规模、体验、业务等多维度价值。
6. 编程智能体不要用代码行数衡量，推荐使用软件交付效能指标和开发者体验调研。
7. 中国市场的营销归因面临私域、跨平台、线下、企业决策等"暗流量"挑战，可以用自报归因、销售访谈、渠道标识、增量实验等方法应对。
8. 为管理层、营销、产品与增长、客户成功设计不同的仪表盘。
9. 警惕虚荣指标、古德哈特定律、只看平均、忽视成本四大陷阱。
