# 第 10 章　产品驱动增长：从注册到"第一个完成的任务"

> 在 Agent 时代，用户的"Aha 时刻"不是看到一个漂亮的界面，而是看到一件事被做完了。

## 10.1 PLG 在 Agent 时代的新含义

产品驱动增长（Product-Led Growth，简称 PLG）是过去十年企业软件领域最重要的增长模式之一。它的核心思想是：让产品本身成为获客、转化和扩张的主要驱动力，用户可以自助注册、试用、付费，无需销售人员的介入。

PLG 的关键概念是"**Aha 时刻**"——用户第一次真正体验到产品核心价值的那个瞬间。对于协作工具来说，Aha 时刻可能是第一次和同事一起编辑文档；对于设计工具来说，可能是第一次做出一张满意的设计稿。PLG 的核心任务，就是让尽可能多的用户、尽可能快地到达 Aha 时刻。

在 Agent 时代，PLG 依然有效，但 Aha 时刻的定义发生了变化。Agent 的核心价值是"替你把事情做完"，所以 Agent 产品的 Aha 时刻是：

> **用户交代的第一个任务，被 Agent 成功完成了。**

我们把这个时刻称为"**首个完成任务**"（First Completed Task，简称 FCT）。FCT 是 Agent 产品 PLG 的核心指标。一个用户如果在注册后很快完成了 FCT，他继续使用、付费、推荐的可能性会大大增加；如果迟迟没有完成 FCT，他很可能就此流失。

本章围绕 FCT，讨论 Agent 产品如何设计产品驱动的增长路径。

## 10.2 Agent 激活漏斗

Agent 产品的激活过程可以用一个漏斗来描述：

1. **访问**：用户访问官网或应用商店页面。
2. **注册**：用户完成注册。
3. **首次任务**：用户给 Agent 交代了第一个任务。
4. **首次成功**：Agent 成功完成了这个任务，用户对结果满意（FCT）。
5. **第二次任务**：用户回来交代了第二个任务。
6. **习惯形成**：用户在一段时间内持续、规律地使用 Agent。
7. **付费**：用户成为付费用户。

在这个漏斗中，有三个特别关键的转化点：

**转化点一：从注册到首次任务。**很多用户注册之后，面对一个空白的输入框，不知道该让 Agent 做什么，于是就离开了。这是 Agent 产品最常见的流失点之一。

**转化点二：从首次任务到首次成功。**用户交代了任务，但 Agent 没有完成，或者完成的质量不满意。第一次就失败的用户，很少会给第二次机会。

**转化点三：从首次成功到习惯形成。**用户体验到了价值，但没有形成持续使用的习惯，过了一段时间就忘记了。

下面我们逐一讨论如何优化这三个转化点。

## 10.3 破解"空白输入框"难题

### 问题的本质

几乎所有 Agent 产品都有一个看似简洁、实则令人困惑的界面：一个输入框，上面写着"有什么可以帮你的？"

对于经验丰富的用户来说，这个界面很好用——他们知道自己要什么。但对于新用户来说，空白的输入框是一个巨大的障碍：

- **不知道能做什么**：Agent 号称什么都能做，但"什么都能做"等于没有告诉用户该做什么。
- **不知道怎么说**：用户不确定用什么样的方式描述任务，Agent 才能理解。
- **担心做不好**：用户担心交代了一个任务，Agent 做不好，浪费时间。

这就是第 4 章所说的"万能的诅咒"在产品体验层面的体现。

### 解决方法一：任务模板

为新用户提供精心设计的任务模板。模板应该：

- **对应黄金任务**：选择 Agent 最擅长、成功率最高的任务作为模板。
- **具体而真实**：不是"帮我写一篇文章"，而是"把这份会议录音整理成会议纪要，按决议事项、待办事项、负责人分类"。
- **可以一键使用**：用户点击模板就可以直接开始，或者只需要填入少量信息（比如上传一个文件）。
- **覆盖不同人群**：根据用户的角色或场景，提供不同的模板。

### 解决方法二：示例任务

提供一个"示例任务"，让用户在不需要提供任何自己的数据的情况下，体验 Agent 的完整工作过程。比如，编程智能体可以提供一个示例代码仓库，里面有几个预设的缺陷，让用户一键让 Agent 修复；数据分析智能体可以提供一个示例数据集，让用户一键生成分析报告。

示例任务的好处是：零门槛、高成功率、能完整展示 Agent 的能力。但它也有局限：用户看到的是"别人的"任务，不是自己的任务，价值感会打折扣。所以示例任务之后，要尽快引导用户用自己的数据尝试真实任务。

### 解决方法三：主动推荐任务

更进一步，Agent 可以根据用户的环境和数据，**主动推荐**任务。这是 Agent 产品相对于传统软件的一个独特优势。比如：

- 编程智能体连接代码仓库后，主动发现："我注意到你的项目有三个失败的测试，要我看看是什么原因吗？"
- 办公 Agent 连接邮箱后，主动发现："你有十二封未回复的邮件，其中三封看起来比较紧急，要我帮你起草回复吗？"
- 财务 Agent 连接 ERP 后，主动发现："本月有五家供应商的对账单还未处理，要我开始对账吗？"

主动推荐不仅解决了"不知道做什么"的问题，还展示了 Agent 的理解能力和主动性，往往能带来强烈的惊喜感。但要注意，主动推荐需要获得用户的数据访问授权，要在隐私和便利之间做好平衡，并明确告知用户 Agent 读取了哪些信息。

### 解决方法四：对话式引导

通过简短的对话了解用户的角色和需求，然后推荐合适的任务。比如：

> Agent："你好！为了更好地帮助你，能告诉我你主要做什么工作吗？"
> 用户："我是一名电商运营。"
> Agent："了解！很多电商运营会让我帮忙做这些事：监控竞品价格、整理每日销售数据、写商品详情页文案。你想先试试哪个？"

对话式引导的好处是个性化，但要控制对话的长度，不要让用户在开始使用之前回答太多问题。

## 10.4 提高首次成功率

用户交代了第一个任务之后，最重要的就是确保这个任务能够成功完成。**第一次的体验，决定了用户对 Agent 的基本判断。**

### 方法一：引导到黄金任务

通过模板和推荐，尽量把新用户的首个任务引导到 Agent 最擅长的黄金任务上。不要让新用户一上来就挑战 Agent 最难的任务。

### 方法二：自动收集上下文

Agent 完成任务的质量，很大程度上取决于它掌握的上下文信息。新用户往往不知道需要提供哪些背景信息，导致 Agent 因为信息不足而做不好。

解决方法是让 Agent **主动收集上下文**：自动读取项目的结构和说明文件、自动分析上传的文件、在信息不足时主动询问关键问题。比如编程智能体在开始任务前，先自动浏览项目结构、阅读说明文件、了解技术栈，而不是要求用户手动提供这些信息。

### 方法三：澄清而不是猜测

当用户的任务描述模糊时，Agent 应该先澄清关键问题，而不是自己猜测。一次简短的澄清（"你希望报告侧重于哪个方面？"），远比完成一个方向错误的任务要好。

但澄清也要有度。如果 Agent 对每个任务都提出一大堆问题，用户会觉得很烦。好的做法是：只澄清那些会显著影响结果的关键问题，对于次要的问题，采用合理的默认值并在结果中说明。

### 方法四：优雅地失败

即使做了所有努力，Agent 仍然可能无法完成某些任务。这时候，**如何失败**就变得非常重要。

糟糕的失败是：Agent 运行了很长时间，最后交出一个明显错误的结果，或者干脆报错退出，用户不知道发生了什么。

优雅的失败是：

- **交付部分成果**：即使没有完全完成任务，也把已经完成的部分交付给用户。
- **说明原因**：清楚地告诉用户为什么没有完成——是信息不足、权限不够、任务超出能力范围，还是遇到了技术问题。
- **提供建议**：告诉用户可以怎么做来帮助 Agent 完成任务，或者建议用户换一种方式。
- **不浪费用户的额度**：对于明显失败的任务，考虑不计费或返还额度。

一次优雅的失败，有时候反而能增加用户的信任：它说明 Agent 是诚实的，不会"不懂装懂"。

## 10.5 降低监督成本

在第 1 章的净交付价值公式中，**监督成本**是一个关键变量。即使 Agent 完成了任务，如果用户需要花大量时间去检查和理解结果，价值也会大打折扣。产品设计必须致力于降低用户的监督成本。

### 结果摘要

Agent 完成任务后，首先给出一个简洁的摘要：做了什么、改了什么、结果是什么、有什么需要用户注意的。用户可以在几十秒内了解任务的整体情况，再决定是否需要深入查看细节。

### 差异视图

对于修改类的任务（修改代码、修改文档、修改数据），用清晰的差异视图展示修改前后的对比，让用户一眼就能看到 Agent 改了哪里。

### 置信度与风险标注

Agent 在结果中标注自己的置信度和潜在风险：哪些部分它很有把握，哪些部分它不太确定，哪些地方需要用户特别关注。这能帮助用户把有限的注意力集中在最需要的地方。

### 一键操作

让用户能够一键接受、一键拒绝、一键要求修改。对于多项结果，支持批量操作。减少用户在审核过程中的操作成本。

### 验证证据

提供结果正确性的证据：编程智能体展示测试通过的结果，研究智能体提供引用来源的链接，数据智能体展示计算过程。用户看到证据，就不需要自己从头验证。

## 10.6 习惯养成：让 Agent 成为日常

用户完成了 FCT，体验到了价值，下一步就是让他养成持续使用的习惯。

### 触发器设计

习惯的养成需要触发器——提醒用户使用产品的线索。Agent 产品的触发器可以分为三类：

**外部触发器**：来自产品外部的提醒，比如邮件、消息推送、办公平台中的通知。"你昨天让我监控的竞品价格有变化了，点击查看。"

**内部触发器**：用户自己产生的使用冲动，通常与特定的场景或情绪相关联。比如每次遇到 bug 时就想到"让 Agent 看看"，每次需要写周报时就想到"让 Agent 先整理一下"。

**自动触发器**：Agent 不需要用户的触发，自己按照预设的规则或时间执行任务。比如每天早上自动生成数据日报、每当有新的代码提交时自动进行代码评审、每当收到供应商对账单时自动开始对账。

**自动触发器是 Agent 产品最强大的习惯养成工具。**一旦用户设置了自动执行的任务，Agent 就会持续地为用户创造价值，即使用户本身不主动使用产品。这大大提高了产品的黏性。

### 嵌入工作流

让 Agent 出现在用户已经在用的地方，而不是要求用户来到一个新的地方。比如：

- 编程智能体嵌入到开发者的终端、编辑器和代码托管平台中；
- 办公 Agent 嵌入到钉钉、飞书、企业微信中，用户在聊天窗口中就可以直接派活；
- 客服 Agent 嵌入到现有的客服系统中。

嵌入工作流降低了使用门槛，也增加了使用频次。

### 渐进式能力解锁

不要在一开始就向用户展示 Agent 的全部能力，那样会让用户不知所措。而是随着用户的使用深入，逐步引导用户发现和尝试新的能力。比如：

- 用户完成了五个简单任务后，提示"你也可以让我同时处理多个任务"；
- 用户使用了一周后，提示"你可以设置定时任务，让我每天自动执行"；
- 用户经常处理某类任务，提示"你可以保存这个任务为模板，下次一键使用"。

### 个性化记忆

Agent 记住用户的偏好、习惯和背景信息，让每一次使用都比上一次更顺畅。比如记住用户喜欢的报告格式、常用的数据源、项目的规范要求。个性化记忆既提高了任务的完成质量，也增加了用户的迁移成本——换一个 Agent，就要重新"培训"。

## 10.7 从免费到付费

### 付费墙的三种类型

**用量墙**：免费用户有一定的使用额度，超出额度需要付费。这是 Agent 产品最常用的付费墙，因为它与成本直接相关，用户也容易理解。

**功能墙**：部分高级功能只对付费用户开放。比如更强的模型、更长的任务运行时间、定时任务、团队协作、高级集成等。

**时间墙**：免费试用一段时间，到期后需要付费。适合需要一段时间才能体验到完整价值的产品。

大多数 Agent 产品会组合使用这三种付费墙。

### 付费的最佳时机

付费转化的最佳时机是用户**刚刚体验到价值，并且需要更多**的时候。比如：

- 用户刚刚完成了一个让他非常满意的任务，并且还想继续使用；
- 用户正在执行一个重要的任务，额度即将用完；
- 用户尝试使用一个高级功能，而这个功能恰好能解决他当前的问题。

在这些时刻展示付费提示，转化率最高。反之，在用户刚注册、还没体验到价值的时候就推付费，或者在用户遇到问题、心情不好的时候推付费，效果都会很差。

### 中国的支付体验

在中国市场，支付体验对付费转化率有很大影响：

- **支持主流支付方式**：微信支付和支付宝是必备的，企业用户还需要支持对公转账。
- **简化支付流程**：尽量减少支付步骤，支持扫码支付、一键支付。
- **提供发票**：个人用户和企业用户都可能需要发票，开票流程要简单便捷。
- **连续包月的合规**：连续包月（自动续费）是提高留存的有效手段，但需要遵守相关的消费者权益保护规定：在开通时清晰告知、在扣费前提醒用户、提供便捷的取消方式。近年来监管部门对自动续费的"默认勾选""取消困难""扣费不提醒"等问题关注较多，违规可能导致投诉和处罚，也会严重损害品牌信誉。

## 10.8 病毒循环：让用户带来用户

### 成果分享

Agent 交付的成果天然具有分享属性：一份精美的报告、一个完整的应用、一段高质量的代码。设计便捷的分享功能，让用户可以轻松地把成果分享给同事、朋友或社交媒体。分享的成果中可以包含适度的品牌标识和"我也要试试"的入口。

### 团队邀请

对于工作场景的 Agent，团队邀请是最自然的病毒循环。当一个用户在工作中使用 Agent，他的同事会看到 Agent 的工作成果，从而产生兴趣。产品可以设计便捷的团队邀请功能，比如"邀请同事一起使用，双方各获得额外额度"。

### 邀请奖励

邀请奖励是中国互联网产品常用的增长手段。但对于 Agent 产品，有几点需要注意：

- **奖励要与产品价值相关**：奖励额外的使用额度，比奖励现金或礼品更能吸引真正的目标用户。
- **防止薅羊毛**：设置合理的奖励上限和反作弊机制，防止批量注册骗取奖励。
- **遵守平台规则**：微信等平台对诱导分享有明确的限制规则，违规可能导致链接被封禁或账号被处罚。邀请机制的设计要符合平台规则。

## 10.9 Agent 引导设计的特殊性

除了上面讨论的方法，Agent 产品的新用户引导还有两个特殊的任务。

### 任务一：期望校准

新用户对 Agent 的期望往往来自于营销内容和社交媒体上的演示，可能偏高也可能偏低。在引导过程中，需要帮助用户建立正确的期望：

- 告诉用户 Agent **最擅长**做什么，推荐从这些任务开始；
- 告诉用户 Agent **不太擅长**做什么，在这些任务上需要更多的人工参与；
- 告诉用户 Agent 可能会犯错，以及如何检查和纠正。

期望校准看似会降低用户的热情，实际上会提高用户的满意度。**满意度 = 实际体验 − 期望**，合理的期望是满意的前提。

### 任务二：培养"管理者"

在第 1 章我们提到，Agent 的用户需要成为"管理者"。新用户引导是培养这种能力的最佳时机：

- **教用户写好任务描述**：通过示例和提示，让用户学会清晰地描述任务目标、背景、约束和期望的结果形式。
- **教用户设定边界**：让用户了解如何设置 Agent 的权限和自主程度。
- **教用户检查结果**：让用户了解如何高效地审核 Agent 的工作成果。
- **教用户给出反馈**：让用户了解如何通过反馈让 Agent 改进。

这些教育内容不应该是冗长的教程，而应该嵌入到使用过程中，在用户需要的时候恰好出现。

## 10.10 增长实验文化

PLG 的成功依赖于持续的实验和优化。建议建立一个专门的增长团队，或者至少建立增长实验的机制。

### 增长实验的流程

1. **发现问题**：通过数据分析发现漏斗中的流失点。
2. **提出假设**：针对流失点提出改进假设，比如"如果在注册后立即展示三个任务模板，首次任务率会提高"。
3. **设计实验**：设计 A/B 测试或其他实验方式来验证假设。
4. **执行实验**：上线实验，收集数据。
5. **分析结果**：分析实验结果，判断假设是否成立。
6. **推广或放弃**：成功的实验全量推广，失败的实验总结经验后放弃。

### Agent 产品的特殊实验维度

除了传统的界面和流程实验，Agent 产品还有一些特殊的实验维度：

- **Agent 行为实验**：比如 Agent 在什么情况下应该主动澄清、什么情况下应该直接执行；首次任务中 Agent 应该更保守还是更积极。
- **默认设置实验**：比如默认的自主程度档位、默认使用的模型、默认的权限范围。
- **引导内容实验**：比如期望校准的表述方式、任务模板的选择和排序。

需要注意的是，Agent 行为实验会直接影响用户的任务结果，要谨慎设计，避免对用户造成损害。

## 10.11 案例：首个完成任务率从三成到七成

> 以下为综合化、匿名化案例，公司名为化名，数字为示意。

"简办"是一款面向职场人士的办公 Agent，能够处理文档整理、数据分析、报告撰写、会议纪要等任务。产品上线后，注册用户增长不错，但团队发现了一个严重的问题：只有约三成的新用户在注册后七天内完成了首个任务，大部分用户注册后就流失了。

增长团队对流失用户进行了调研，发现了三个主要原因：

1. **不知道做什么**：很多用户面对空白输入框，不知道该让 Agent 做什么。
2. **第一次失败**：一部分用户尝试了任务，但结果不满意，就没有再回来。
3. **忘记了**：一部分用户注册时有兴趣，但之后就忘了这个产品。

针对这三个问题，团队进行了一系列实验：

**实验一：角色化模板。**注册后增加一个简单的问题："你的工作主要是什么？"根据用户的回答（行政、销售、运营、财务、人力、技术等），展示三个最适合该角色的任务模板。实验结果显示，首次任务率显著提升。

**实验二：首个任务保护。**对于新用户的前三个任务，Agent 采用更保守的策略：遇到模糊的任务描述时更积极地澄清，在结果中更详细地说明做了什么，失败时提供更具体的建议。同时，如果新用户的首个任务失败，系统会自动返还额度并推荐一个成功率更高的任务。实验结果显示，首次成功率明显提升。

**实验三：办公平台接入。**引导新用户把 Agent 接入自己的办公平台（钉钉、飞书或企业微信），这样用户在日常的聊天窗口中就可以直接 @Agent 派活。实验结果显示，接入办公平台的用户，七日留存率是未接入用户的两倍以上。

**实验四：第一个定时任务。**在用户完成第三个任务后，推荐用户设置一个定时任务（比如"每周五下午自动整理本周的工作周报草稿"）。设置了定时任务的用户，三十日留存率显著提升。

经过三个月的持续实验，简办的首个完成任务率从三成左右提升到了七成左右，三十日留存率和付费转化率也有了显著的提升。

### 案例启示

1. **首个完成任务率是 Agent 产品 PLG 的核心指标**，值得投入大量资源优化。
2. **个性化的任务推荐**能有效解决"空白输入框"难题。
3. **新用户需要特别的保护**，第一次的体验决定了用户的去留。
4. **嵌入工作流**是提高留存的有效手段。
5. **自动触发器**（定时任务）是 Agent 产品最强大的习惯养成工具。
6. **持续的实验**是增长的引擎。

## 本章要点

1. Agent 产品的 Aha 时刻是"首个完成任务"（FCT），它是 Agent 产品 PLG 的核心指标。
2. Agent 激活漏斗有三个关键转化点：从注册到首次任务、从首次任务到首次成功、从首次成功到习惯形成。
3. 破解"空白输入框"难题的四种方法：任务模板、示例任务、主动推荐任务、对话式引导。
4. 提高首次成功率：引导到黄金任务、自动收集上下文、澄清而不是猜测、优雅地失败。
5. 降低监督成本：结果摘要、差异视图、置信度与风险标注、一键操作、验证证据。
6. 习惯养成：触发器设计（自动触发器最强大）、嵌入工作流、渐进式能力解锁、个性化记忆。
7. 付费墙有用量墙、功能墙、时间墙三种，付费的最佳时机是用户刚体验到价值并需要更多时。中国市场注意支付体验和自动续费合规。
8. 病毒循环：成果分享、团队邀请、邀请奖励（注意平台规则）。
9. Agent 引导的两个特殊任务：期望校准和培养"管理者"。
10. 建立增长实验文化，关注 Agent 行为、默认设置、引导内容等特殊实验维度。
